## 界面与行为

- Windows 标题栏使用系统移动与缩放：左右吸附半屏、顶边最大化，从吸附／最大化状态拖出可还原。
- 首页「YOUR LIBRARY / 我的媒体」右侧增加全屏／窗口按钮，状态与 F11、原生窗口状态保持同步。
- 顶部消息、投屏、搜索、更新、全屏、MPV、账号和设置按钮统一尺寸、圆角与反馈；保留消息数量、更新红点与 MPV 金色标识。
- 设置的「首页设置」增加「启动时自动全屏」，默认关闭。保存后下次启动生效；按钮或 F11 不修改启动偏好。显式启动命令行与 kiosk 配置保持优先。
- 修复窄屏触控布局中首页第一排高度不足而裁切媒体入口的问题。

## Windows 原生检查

真实鼠标输入检查使用独立测试窗口，先验证标准 Windows 边框，再验证自绘标题栏；不会操作用户安装版。标准窗口与产品窗口管理器均通过左右吸附、顶边最大化和拖出还原。测试包含 2 个用例及初始化／清理，共 **4 passed、0 failed、0 skipped**。

两台显示器的连续最大化／全屏／还原检查通过。另在系统 150% 缩放上额外设置 `QT_SCALE_FACTOR=1.25` 重复两屏检查，**4 passed、0 failed、0 skipped**；此项不代表把 Windows 系统缩放改成 125%。

测试发现并修复：自动隐藏任务栏时，工作区可能等于整屏，Qt 6.9 会把最大化误报成全屏。原生最大化客户区现在仅在这个条件下按自动隐藏任务栏边缘保留 1 物理像素，避免隐藏自绘标题栏；真正全屏保持原有路径。先复现失败，再通过延迟窗口状态断言确认修复。

本地原始报告：`build/native-edge-drag-final.txt`、`build/native-snap-scale125.txt`。所有原生检查均在同一 PowerShell 调用中加载 `dev/windows/Enter-TestEnvironment.ps1`，预检 MPV、RIFE、Qt 与平台插件。

## 自动化与预览范围

Windows 完整 CTest **81/81 目标通过**，用时 330.55 秒。之后补做整包重启检查，发现 MPV 初始 `fullscreen=false` 被隐藏播放区域转发、覆盖首页启动偏好的问题；旧包上新增回归先失败，QML 仅在播放区域显示时接受这条通知后通过。新增长期回归 `test_window_startup_webengine`，测试总注册数变为 82；最终对受影响的窗口、启动、音量和播放 9 个目标复测，**9/9 通过**，用时 49.34 秒，没有宣称对这次末尾修复重跑全部 82 个目标。

启动回归通过四个真实独立客户端进程，覆盖默认窗口、偏好全屏、实际首页按钮、磁盘保存以及双向重启。保存偏好时特意让当前窗口处于相反状态，确认设置不会立即切换窗口。

另使用本地合成 Y4M 视频、真实 libmpv 和 QML，检查播放区域可见时 MPV 命令仍能进入／退出全屏，停止后回到窗口。首次检查在播放界面刚出现时过早发命令，加入原生状态读取确认后通过；没有为这项时序校准修改产品代码。此项是本地播放链路验证，不是生产影视媒体或长时间性能测试。

完整套件内部明确跳过 7 个 Qt 用例：2 个需要真实鼠标独占的吸附用例（已单独 opt-in 实测通过）、3 个原有鼠标隐藏／指针恢复用例、1 个旧纯 frameless fixture 的最大化检查（本机所有工作区等于整屏；新增产品窗口管理器测试另行通过）、1 个需要私有已验证 RIFE 运行库的启动探针。CTest 目标全部通过不代表这些用例都在默认套件执行。

独立 Chromium fixture 已验证按钮状态、失败恢复、延迟调用、F11 信号、触控点击范围，以及首页六个尺寸、长标题与减少动态效果的布局。截图使用真实页面渲染与示例媒体，工具栏字体来自 Emby；不代表用户实际媒体库截图。

Android Debug 116 项、Release 113 项 JVM 测试通过，lint 无错误、43 条警告。最终 Android Debug APK 已重新打入本次共享界面资源并核对文件字节与 16 KB 对齐；不是正式签名发布包，没有进行 Android 真机交互验收。

独立代码复审完成，已修复发现的窄屏裁切问题，无剩余确认缺陷。
