# 2026-10-13 窗口播放持续掉帧调查

## 结论与边界

预览 6 在用户主动打开的同一集上复现了持续输出丢帧。窗口模式的呈现节奏不稳定，与 `display-resample` / `display-vdrop` 的显示时钟同步发生冲突；纯 `audio` 时钟的对照采样未新增丢帧。解码丢帧一直为 0。尚未确认造成窗口呈现节奏异常的底层因素，不能据此断言为驱动、G-SYNC、DWM 或 Qt 中某一个组件的缺陷。

这次没有把音频时钟作为正式修复写入产品：弹幕插件会把普通 audio 自动提升为 display-vdrop，以便在视频帧之间重绘弹幕，直接改设置并不能解决本例。绕开此行为能停止新增输出丢帧，但可能影响弹幕运动流畅度，尚需兼顾这两项行为的后续修复。

## 真实播放对照

用户使用独立的 Preview5 试用配置在预览 6 主动播放《来自远方》第 1 集，沿用已有登录，不复制凭据，不创建生产测试评论。对该实例通过本机 MPV IPC 采集白名单性能属性；记录中不包含媒体 URL、请求头或令牌。硬件为 RTX 4090，主屏 3840×2160 / 240 Hz，GPU-Next / D3D11，d3d11va-copy，RIFE 关闭。

下面各段均剔除开头 5 秒，按计数差值统计，避免把切换瞬间计入持续播放故障。

| 模式 | 稳定采样时长 | 新增输出丢帧 | 新增解码丢帧 |
| --- | ---: | ---: | ---: |
| 窗口 / display-resample | 14.561 秒 | 11 | 0 |
| 全屏 / display-resample | 24.594 秒 | 0 | 0 |
| 再回窗口 / display-resample | 19.591 秒 | 13 | 0 |
| 窗口 / 纯 audio | 19.574 秒 | 0 | 0 |
| 隐藏网页内容 / display-resample | 19.583 秒 | 10 | 0 |
| 窗口 / 关闭 flip-model | 14.568 秒 | 64 | 0 |

窗口段估计呈现频率波动明显；第一次全屏段最终接近 240 Hz，VSync jitter 约 0.011。audio 段的估计刷新值不再更新，不能把其保留值视为切换后的实际刷新率。

普通 audio 实验实际被弹幕插件切换为 display-vdrop，24.609 秒仍新增 16 帧。纯 audio 对照临时使用插件既有的时钟所有权标记，阻止插件改回显示时钟；此标记并未启用 RIFE。实验后恢复标记为 false、video-sync 为 display-resample、d3d11-flip 为 true，并移除临时网页样式。所有改变均为当前实例的内存状态，未写入用户设置或生成发行配置。

隐藏网页内容未解决问题；关闭 flip-model 更差，均未保留。全屏日志明确为非独占模式，不能以“全屏采用独占模式”解释本次结果。

## 隔离测试限制

此前本地生成视频的两组隔离测试没有复现输出丢帧，但其 native load 调用未选中音轨，缺少实际音画同步条件，因此不能作为此故障的反证。真实播放样本以上表为准。

原始白名单采样在忽略的 `build/window-pacing-live-*.json`；稳定段摘要保存为本目录 data 中的 `2026-10-13-windowed-presentation.json`。本次只调查并记录窗口问题，没有发布版本或合并 PR。共享弹幕 OSD 的预览 6 改动和验证见同目录 `2026-10-13-shared-osd-preview6.md`。

参考：[mpv 官方手册的同步模式说明](https://mpv.io/manual/stable/#options-video-sync)将 audio 定义为跟随音频的稳健模式，并说明显示同步模式依赖呈现时序；这支持实验设计，不单独证明当前系统的底层故障原因。
