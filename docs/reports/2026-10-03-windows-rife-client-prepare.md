# Windows RIFE：完整客户端回归与首次准备

## 复现范围

- 已安装的 V2.3.2 客户端，完整 Emby 页面发起网络播放，包含 UOSC、字幕和弹幕。
- Windows、RTX 4090、驱动 32.0.16.1664、3840×2160 / 240 Hz 显示器。
- 1920×1080 H.264 8 bit、24000/1001 fps、逐行 SDR、AAC 音频；从同一恢复位置播放。
- 模型 4.25、约 60 fps 档位（实际 2 倍 / 47.952 fps），内置默认画质与三条 Shader。
- 使用独立配置副本做对照，保留原有安装和配置。验收资料不包含媒体地址或认证信息。

## 已确认的原因

真实客户端在 `video-sync=display-resample` 时重复触发回退。典型回退记录为 370 对已处理源帧、101 个 VO 丢帧、0 个解码丢帧、约 -2.17 ms 音画偏差。关闭弹幕后仍发生回退，不能将问题归因于弹幕本身。

只将同步方式改为 `audio`，保留全屏、网络片源、弹幕与画质处理，连续 40 秒对照保持 Active；切回 `display-resample` 后再次于约 15 秒触发回退，再切回 `audio` 又保持 Active。此证据定位于显示时序组合，不代表所有显卡、驱动和显示器都存在同样问题。[mpv 同步方式说明](https://mpv.io/manual/stable/#options-video-sync) 也区分了依赖显示垂直同步与音频时钟的时序路径。

修复将 Windows TensorRT 补帧期间的同步方式交由补帧生命周期管理，结束、旁路或失败后恢复用户偏好。未放宽丢帧比例、音画偏差或保护时间阈值。

V2.3.2 的本地素材和 video-only 测试没有覆盖该完整 Emby 使用组合，其通过结果不能外推到本次用户场景。

## 扩展体积

原完整 ZIP 为 2,146,337,426 bytes。七种最终包均逐文件校验及客户端版本范围检查通过，保留 PTX、公共 DLL 与三模型。sm89 最终包为 825,606,391 bytes，减少 61.53%；各架构包约 724–1040 MiB。完整兼容包保持原始字节与哈希。最终封装的元数据与哈希见发布清单。

sm89 试包在 RTX 4090 上完成了新的 256×128 lite 引擎编译及真实推理验证，耗时约 44 秒；`cacheHit=false`、`validatedInference=true`。未知、多显卡或无法确认架构的环境继续选择完整包。其他架构只完成封装校验，尚无对应 GPU 播放实测。

## 集成验收

最终源码构建与最终 sm89 扩展通过完整客户端验证。通过原生文件选择窗口导入 ZIP，完整核验后重启，确认启用的是适配包。使用独立的已登录配置副本，从 Emby 播放管理器发起实际网络视频播放，保留全屏、默认画质、字幕、UOSC 与弹幕；不是 video-only 播放器测试。

| 模型 | 首次准备与当前项继续 | 连续 Active 采样区间 | 区间末处理对数 / 生成帧数 | 性能回退 |
| --- | --- | --- | --- | --- |
| 4.25 lite | 准备约 60 秒后自动继续 | 125 秒 | 3019 / 3005 | 无 |
| 4.25 | 准备时按空格，完成后保持暂停；再按空格继续 | 115 秒 | 2778 / 2766 | 无 |
| 4.25 heavy | 准备约 65–70 秒后自动继续 | 105 秒 | 2653 / 2641 | 无 |

连续区间是每 5 秒采样得到的已观察时段，并非长期稳定性或其他硬件的保证。画面观察确认等待遮罩自动撤下、视频正常渲染。4.25 另观察到自动进入下一集并复用引擎；heavy 回退 20 秒定位后恢复 Active 并继续生成帧。

准备期间播放位置保持不变；4.25 在用户主动暂停、编译完成后继续保持同一位置至少 30 秒。lite 首次准备约 30 秒时执行停止，等待画面立即撤下并回到详情页，准备状态清除；再次打开同一项可重新准备并自动播放。停止后有效同步方式恢复为用户保存的 `display-resample`。

启动核验窗口在实际 Windows 150% 缩放下观察为深色窗口、完整对齐的金色进度轨道，显示文件核验／运行库探测阶段及耗时。后续启动用时约 3.21 秒到本地接口就绪，108 个扩展文件复用校验记录，重新读取哈希的字节数为 0；此时间不包含 Emby 网络页面完成登录和加载的时间。重新打开 4.25 同一视频，5 秒内采样到 `engineCacheHitForItem=true`、Active、99 对处理帧与 97 帧生成，没有重新编译引擎。

## 自动化验证与边界

- 最终本地完整 CTest：60/60 通过，101.87 秒。包括实际 GPU 播放、暂停／定位／重开、准备生命周期、异步恢复应答、遮罩清除、启动窗口与架构选择。
- Web 播放层的 30 秒启动检查只在原生准备状态有效时延长；原生桥超时、准备过期、停止后旧异步结果、主动暂停均有回归覆盖。
- 原生回归覆盖停止、换片、准备失败与超时；这些故障分支没有通过破坏用户真实扩展来重现。真实客户端覆盖首次准备、暂停、停止后重开、定位及自动换集。
- 三模型播放实测均为 RTX 4090 上约 60 fps 档位，23.976 fps 输入实际输出约 47.952 fps；不把此结果外推到 120／240 fps、4K 输入或其他 GPU。
- 七个架构包均完成完整性和版本范围检查；仅 sm89 有实际 GPU 编译与客户端播放验证。
- Windows／Mac CI 和最终发布文件校验记录单独写入该版本发布清单；Mac 本次没有本地交互播放实测。
