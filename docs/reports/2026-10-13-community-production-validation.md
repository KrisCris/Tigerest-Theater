# 2026-10-13 评论密码与头像生产联调

## 范围

后端新能力已上线。使用当前评论实现的独立 Windows 预览包，通过真实 QtWebEngine、原生 HTTP 桥和 Windows 安全凭据存储访问生产评论 API；没有改动用户安装版或其配置。

头像来源使用独立本地 HTTP Emby fixture，图片经真实原生解码、缩放、PNG 编码与 SHA-256 计算后上传。此项验证中央生产 API 与客户端原生处理链路，不等同于任意自建 Emby 服务器实测，也不代表新增窗口功能已经验收。

## 已通过

- capabilities 宣告 8–128 个 Unicode 码点密码及 sha256-on-comment 头像协议。
- 7 字符密码在本地拒绝；包含 emoji 的恰好 8 字符密码可注册并登录，会话保存至系统安全存储。
- 发送主评论携带头像 hash，成功后按后端返回的版本上传 PNG。鉴权读取的图片与上传文件字节一致。
- 客户端原生桥拒绝匿名头像请求；直接访问生产头像接口也返回 401。
- 回复时头像不变不触发上传；相同 hash 和原版本重复 PUT 不增加头像版本。
- 来源头像变化触发新图上传；旧版本覆盖新图返回 409，现有头像保持不变。
- 来源暂不可读时省略头像字段，评论仍可发送，中央头像保留。
- 来源明确无头像时按版本清除中央图片。
- 修改密码后，旧 access token、refresh token 和旧密码均失效；新密码可登录。改密清理本地旧会话。

## 清理与限制

全部测试评论和回复已逐条删除，测试头像已清除，评论会话已退出，隔离配置中的系统凭据已确认删除。测试脚本校准及完整测试共创建 4 个随机独立账号、8 条测试发言；账号记录没有公开删除接口，因此保留为测试身份，不包含真实用户凭据。删除评论是否保留后端审计或占位记录由服务端策略决定。

测试脚本首次将原生桥匿名拒绝误判为应返回 HTTP 401，校准为分别检查桥层拒绝和生产 HTTP 401 后完整通过；未因此修改产品代码。最终机器可读记录保存在本地 `build/release260-live-avatar-validation.json`，仅含检查状态，不含密码、令牌或真实账号信息。

本报告不宣称已验证 Android 真机网络、macOS 实机播放或高频限流。客户端取消、账号切换、上传失败重试等边界由隔离 fixture 回归覆盖。2.6.0 发布仍需新增窗口功能预览确认。
