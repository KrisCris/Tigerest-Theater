# Mac 120 Hz 界面验证

测试机：M4 Pro（14 核 CPU / 20 核 GPU，48 GB），macOS 27.2、Xcode 27.2 beta。应用最低版本仍为 macOS 26。内置屏幕 120 Hz；全屏客户端逻辑视口 1800×1130、DPR 2。基础基准使用独立配置和本地模拟媒体库；后续真实媒体库验证使用账号的临时隔离副本，结果单列如下。

## 结论

保留 Qt 桌面架构就能解除 60 Hz 限制。原版 Qt WebEngine 向 Chromium 提供了无效的 Mac 显示器 ID，导致其回退到 60 Hz 定时器。修复后使用真实显示器的 display link，按显示器刷新率工作。单纯把 OpenGL 换成 Metal 无法解决这个限制。

此外修复了跨 JavaScript 执行环境的转场协调，避免重复入场动画；快照不再构建隐藏页面或屏幕外海报的完整子树；独立透明输入层替代对整个页面继承的 pointer-events 切换，降低转场起步开销。

## 结果

| 项目 | 实测 |
| --- | --- |
| 原版简单页面 | 约 60 rAF/s、60 次 Qt 窗口提交/s |
| 修复后简单页面 | 约 118–120 rAF/s、约 117–120 次 Qt 窗口提交/s |
| 60 Hz 屏幕模式 | 59.995 rAF/s，约 60 次 Qt 窗口提交/s，无超额绘制 |
| 独立预览包全屏连续滚动，最终三轮基准 | 120 rAF/s，p95 8.7 ms，最长 10.3 ms |
| 首页飞出动画，六次采样 | 约 120 rAF/s，未记录到估算漏刷新 |
| 独立预览包转场，最终三轮基准 | 各场景平均约 109–118 rAF/s；最差单帧间隔 91.7 ms |
| 静止页面 / 实际隐藏窗口 | 均为 0 次 Qt 窗口提交 |

这些是调度和提交指标，不能直接等同于屏幕实际显示帧数。Instruments 对简单页面的系统呈现回调也从约 60/s 提升到约 116/s（中位间隔从 16.665 ms 降到 8.335 ms）；完整界面尚无逐帧扫描输出测量。完整转场偶发准备停顿仍然存在，不能宣称所有页面全程稳定 120 fps。

预览包首次运行另记录到最长约 316 ms 的首帧等待和 283 ms 的后续帧间隔；不能用后续较快结果掩盖这次冷启动卡顿。最终统计已修复评审发现的首段漏算问题：先采集一个 rAF，再触发转场，保留初始间隔及独立首帧延迟。250 ms 人工阻塞回归先失败后通过，相关单元测试 18/18 通过。最终三轮报告为 `portable-fullscreen-inclusive.json`，早期 interval-only 数据不能用作完整转场验收。

## 播放兼容性

独立签名预览包通过依赖闭包和 RIFE 模型检查，播放期间未借用开发机上的 mpv、Qt 或 Python 库。使用 1080p30 BT.709 本地测试视频、真实音频设备并静音：

- 默认 GPU-Next 连续一分钟：0 解码掉帧、0 渲染掉帧，最大音画偏差 19.6 ms，三项默认 shader 均加载。
- RIFE 30→60：一分钟产生 1805 张插帧，持续播放掉帧率 0.083%，最大音画偏差 18.0 ms。启动阶段另有 4 帧掉帧，超过现有严格测试的 2 帧门槛，因此严格启动验收仍未通过。
- libmpv/OpenGL 兼容模式：候选包启动掉 13 帧，原安装版同条件掉 12 帧；两者都未通过启动门槛，未据此宣称该模式完整验收通过。

以上是本地视频的真实原生播放验证，不是生产 Emby 网络、HDR、所有编解码格式或长时间稳定性验证。

## 使用与发布边界

预览用单独启动脚本指定独立配置目录，需要重新登录。安装版及其配置保持不变。补丁、构建和基准复现步骤见 `dev/macos/qt/README.md`。引擎补丁尚未接入正式发布流水线。

实际最小化未在测试工具中成功触发，不能把工具的失败当成最小化窗口仍绘制的证据。多显示器迁移、低电量模式及真实服务器重负载仍待验证，因此当前交付定位为本机预览，不替换正式版。

## 评审与取舍

一次独立整分支评审未发现已确认的产品代码阻塞问题；重要的统计缺陷已按失败→修复→通过验证。正式发布前仍需扩展屏幕外海报占位的 flex、自适应宽度和横向滚动几何测试；现有精确几何回归覆盖固定轨道布局。

- 保留 Qt、修复显示器时钟，而未重写为 iPad 外壳：已有运行证据定位到这一瓶颈，避免桌面功能迁移风险；代价是需要维护定制引擎补丁。
- 基准默认采用页面驱动滚动：Qt 无法完成 CDP 合成滚轮命令；代价是真实触控板输入还需单独体验。
- 未验证的多屏、节能、最小化及网络/HDR/长时播放场景留作正式发布门槛：当前只交付本机独立预览，不能将局部结果外推为全面兼容。
- RIFE 和 libmpv 的严格启动失败保留为失败，不通过放宽门槛获取绿灯；预览仍可能遇到启动掉帧。

测试原始 JSON 和 Instruments 数据保存在本机 `/tmp/tigerest-mac-120hz/`；原始 trace 包含进程环境信息，不随代码或预览包发布。

## 后续真实媒体库验证

使用现有账号的临时隔离副本，只浏览媒体库；测试结束即删除副本。真实海报墙滚动测得 119.98 rAF/s、p95 9.0 ms。真实 Emby 使用 `page-hidden` 隐藏旧页，并用绝对定位的虚拟海报列表；已补齐这两种布局的快照裁剪，回归验证可见海报的位置和滚动位置不变。

追踪发现，切页后旧首页预热继续批量解码海报，曾让主线程阻塞 195.7 ms。现在进入媒体库或返回首页时会取消不再需要的预热，仍保留已经完成的快照。重新编译后的三轮真实进入媒体库平均 105/112/113 rAF/s，最长间隔约 33 ms；返回首页约 117 rAF/s。相关单元测试 18/18，真实 WebEngine 的快照与转场回归均通过。

随后更细的动画阶段测量仍捕获到一次新页面首次绘制的 83 ms 间隔，说明尚未全程稳定 120。临时增加预绘制等待未显示明确收益，因此没有纳入产品。

## 海报转场的解码复用

真实首页→详情再次暴露了同步大图解码，曾出现 165–175 ms 的长帧。现在按不可变资源或 Emby 图片版本标记保留小尺寸解码结果，较小面板可复用较大结果；普通可变 URL 不缓存。缓存最多 64 项、4 百万像素（约 16 MiB RGBA），每次构建拥有独立可传输副本，换图、淘汰与销毁都有回归覆盖。没有增加图片网络请求。

重新编译并签名的 `2409483` 预览包，真实媒体库三轮结果：

| 路线 | 第 1 / 2 / 3 轮 rAF/s | 三轮最长帧间隔 |
| --- | --- | --- |
| 首页→详情 | 104.77 / 113.44 / 114.50 | 50.0 ms |
| 详情→海报墙 | 113.64 / 116.60 / 116.62 | 33.3 ms |
| 海报墙→首页 | 117.55 / 117.54 / 118.53 | 34.5 ms |

中间版本另记录过一次 200 ms 间隔，最终三轮没有复现，但不能据此保证已经根除所有长帧。首次新图解码与页面准备仍是后续目标。完整毛玻璃替代方案、额外预绘制等待等实验没有稳定收益，均未采用。匿名汇总见 `2026-10-14-mac-poster-cache-metrics.json`；原始带网络上下文的 trace 不发布。


## 小尺寸背景图的后台解码

对本机定制引擎增加一个限定范围的补丁：仅将 macOS 上同时指定宽高、输出不超过 240×512 的图片解码移入工作线程。原有裁剪、方向、颜色、透明度及同源限制保留；DOM 和编码数据在调用时取快照，不增加网络请求。该补丁已完成本机预览验证，尚未接入正式发布。

在同一套合成图片上，底层调用同步占用由最慢 73.5 ms 降到独立包的 2.0 ms。18 项输出像素哈希与原引擎完全一致，涵盖透明度、ICC、EXIF、裁剪、缩放滤镜、16 位输入、动图首帧和调用后换图；跨域像素读取和转移继续被拒绝。真实 WebEngine 的图片缓存、转场几何和点击回归通过。另补充了来源子页面关闭后父页面仍能收到正确图片的测试，并明确由调用页面接收结果；旧版复现测试也通过，因此这是生命周期加固，不宣称修复了已复现的故障。

特意在每次海报转场前清空背景解码缓存和转场快照，在相同真实媒体库做前后对照（**这是冷缓存压力实验，不是普通导航**）：

| 路线 | 旧引擎第 1 / 2 轮 rAF/s | 新引擎第 1 / 2 轮 rAF/s | 最长间隔：旧→新 |
| --- | --- | --- | --- |
| 首页→详情 | 76.77 / 85.16 | 109.56 / 117.18 | 209.7→32.2 ms |
| 详情→海报墙 | 95.55 / 114.12 | 114.96 / 116.62 | 75.0→18.0 ms |

普通三轮导航没有明显整体提升：首页→详情 99.10/113.64/114.38，详情→海报墙 110.69/116.64/115.40，返回首页 118.03/118.03/117.57；首次仍有 66.7 ms 间隔。已命中缓存的解码通常不足 1 ms，其余页面准备和绘制仍需优化，不能把 API 加速等同于全程 120 帧。

新引擎独立包重新通过原生 GPU-Next 连续 60.382 秒播放：启动掉帧 0、渲染掉帧 1（0.055%）、解码掉帧 0，最大音画偏差 28.9 ms，三个默认 shader 生效，没有借用开发目录中的依赖。这是新样本，不能沿用前一引擎“零渲染掉帧”的说法。匿名数据见 `2026-10-14-mac-async-bitmap-metrics.json`。


## 转场快照不再初始化控件

真实页面诊断发现，复制静态画面时，`cloneNode` 会再次构建并启动 Emby 的滚动器、标签栏等控件，快照自己的滚动回调还触发过10.5ms布局。现在快照中的定制内置控件使用普通同标签元素，保留外观属性、输入状态和滚动位置。真实页面继续使用原控件，SVG和独立自定义标签的复制路径不变。

新增原生回归先因额外构造控件而失败，修复后通过：重复构造/连接次数为0，横纵滚动位置、外观选择器、精确尺寸、文本、复选框及文件选择状态均保持。20项相关Node回归与原生转场/缓存/点击回归通过。

同一进程A/B/A实验中，进入海报墙的最长间隔从33.3–33.7ms降到24.9–25.0ms，平均帧率有小幅改善，返回首页没有明确收益。最终重新编译的`7eb5cf2`独立包三轮真实媒体库测量：首页→海报墙105.71/114.14/115.05rAF/s，最长25.1ms；海报墙→首页117.07/117.56/117.55rAF/s，最长25.0ms。首次路线平均帧率仍偏低，未宣称已经全程稳定120。原始匿名汇总见`2026-10-14-mac-static-snapshot-metrics.json`。

另试过对详情页增加布局隔离；本次几何对照不变，但帧率没有明确改善，因此未采用。

## 背景换图只更新背景层

`87fcd1b` 将背景图片变量从页面根节点移到背景容器，避免整页和隐藏页面继承这些变量。真实详情页上，受控 A/B/A 测量的样式重算由574–949个元素缩小到3个，耗时约3.6–13.6ms降到0.09–0.24ms。保留根节点上的淡入阶段标记；单独测量确认该标记同样只更新3个元素，且能让重建后的背景直接显示正确图层。

模糊强度和850ms淡入保留。原生客户端三个动画中间画面的像素哈希与原实现完全一致，换图、失败回退、背景重建、脚本世界间转场协调均通过。重新编译、签名后的独立包通过相同像素对照和依赖检查。
