# 自动弹幕匹配与 ede.js 评估

## 后续修订：桌面取消日期确认

2026-10-09 18:38 播放《转生成为魔剑了》S02E02 时，客户端元数据的集号为 2，但首播日期为 2026-10-15。弹幕目录中第 2 集 177890002 的日期为 2026-10-08，第 3 集 177890003 的日期为 2026-10-15。旧桌面匹配器将唯一的精确日期候选直接选中，覆盖了集号，实际请求第 3 集弹幕。

桌面后续修订完全移除自动检索中的日期选集、日期距离排序和七天否决条件。候选必须与请求的正片集号一致，再依次按作品标题、单集标题和完整提供方/作品/单集 ID 稳定排序。没有真实文件哈希的 Emby 流媒体统一查作品目录，不再以日期是否有效决定匹配路径。连续集号与分季集号的对应关系需要共享规则或明确的手动选择。共享接口及保存行为不变，Android 日期策略本次未调整。

以下日期策略与验证记录描述此前版本。后续修订使用真实 libmpv 加载 Lua 回归夹具验证本次 S02E02 案例、缺失/无效/冲突日期、跨季编号、片头片尾排除、候选排序和手动/共享优先级；不代表已打包安装或完成真实视频播放验证。

## 本次失败的证据

报错附件记录 2026-10-09 02:37:29 自动匹配失败，随后同一搜索词手动选择第 1 集于 02:37:41 加载 735 条弹幕。只读查询生产 NAS API 确认作品 19310 的第 1 集为 193100001，“第1话 开始与结束”。作品和集数均可以识别。

Emby 首播时间是 `2026-01-08T16:00:00Z`，上游日期是 `2026-01-09T00:00:00`。相差一天原本允许走一周内的匹配，但作品目录另有 `C1 Opening`、`C2 Ending`。旧代码将这两个非正片编号视为不完整数据，对整个候选列表设置否决标志，造成漏匹配。

## 用户确认的新取舍

优先得到可用的自动识别结果，允许少量错误，通过 OSD 展示结果和手动纠正来恢复。共享纠正规则优先于自动检索，只有明确的手动选择才写入共享规则。

桌面识别保留已有作品检索范围，排除非正片 C 编号；匹配相同集数时，标题不同、缺失有效日期或其他候选查询失败不再否决已有结果。可比较的日期超过 7 天仍不采纳。在多个候选之间，依次比较作品标题相似度、单集标题相似度、日期距离，最后用完整提供方/作品/不透明单集 ID 稳定排序。精确日期仍优先，精确单集标题可以识别连续集号与分季集号之间的对应关系；没有集数或标题证据的批量同日发行仍不猜测偏移量。

OSD 保留作品名、单集名称和条数，显示五秒并提示从弹幕菜单手动纠正。日志增加候选数量、排除的片头片尾数量、日期距离等结构化结果，便于判断后续的漏匹配。

## ede.js 中可参考的部分

所提供的 `ede.js` 是 Emby Danmaku Extension 1.47。

- `searchEpisodes` 将哈希匹配、带集数搜索、不带集数搜索、缓存与原标题检索串联，能提高检索覆盖率。后续可以在现有 NAS 接口支持的范围内增加原标题作为备用检索词。
- 从 Emby 的 SeriesName、ParentIndexNumber、IndexNumber 构造作品和集数，使用同一作品/季的校准偏移。这与当前使用原视频 source、手动选择真实 episodeId 后保存共享规则的方向一致。
- 将手动选择结果缓存、允许用户检查和修正自动结果，符合本次要求。

不应直接整份替换当前播放器。脚本有在部分路径取第一个作品结果的行为，哈希失败时使用占位假哈希，某些旧回退调用未传 prefix；`tmdbAutoFailback` 还引用未定义的变量，实际没有使用 tmdbId。它的主要新版流程使用 `/search/episodes`，当前 NAS 托管路径是否提供这个接口需要另行核对。上述备用检索方案属于评估建议，本次没有新增第三方代理或这些接口调用。

## 验证范围

原失败由包含真实 C1/C2 条目的回归夹具复现，修复后通过。新策略验证重复候选、译名、缺失日期、失败/超时的其他查询、稳定排序、OSD 内容，以及一周边界、真正缺失集数和换片取消。

使用真实元数据运行原生 libmpv 中的 Lua 匹配器，匿名读取生产作品目录、单集目录及弹幕接口，自动选中 193100001“第1话 开始与结束”并取得 735 条弹幕。该验证使用暂停的合成音频维持异步请求环境，没有播放用户的真实视频，也没有向生产共享规则或报错接口写入数据。报错上传的生产行为来自用户本次提交的实际附件，不把夹具提交当作生产验证。
