# V2.3.2 Windows RIFE 稳定性与启动验收

本次处理 Windows 频繁退出补帧以及每次启动重复校验大型扩展的问题。验证使用隔离配置、测试客户端和真实视频片段，没有修改用户正在使用的客户端、设置或扩展。

## 复现与修复

- 真实 1080p、24000/1001 fps 动画在旧逻辑中将“约 60 fps”选成三倍，输出 71.928 fps。同片段旧逻辑在约 15 秒时已有 854 次 VO 丢帧和 1.209 秒音画差，随后退出补帧。精确 24 fps 合成视频则选择两倍，短测正常。
- 倍率选择现在将 NTSC 帧率归入对应的标称 24/30/60 fps 档，但播放时间戳仍保留真实帧率。23.976/24 fps 在约 60 fps 档输出 47.952/48 fps，30 fps 输出 60 fps。保持整数倍方案及原视频时长；120/240 fps 仍属实验方案。
- mpv 的 VO 丢帧计数包含输出帧率高于显示刷新率时的正常省略。保护现在扣除预期显示节奏，并在刷新率变化时重新建立丢帧窗口，避免把旧刷新率的计数用于新刷新率。持续音画偏差及额外丢帧仍触发保护。
- 原启动流程先完整校验扩展，再通过公共运行库探测程序重复读取同一份约 2.7 GB 内容。现在由原生扩展管理器校验成功后直接执行隔离的私有显卡／运行库探测；独立运行库入口仍保留完整校验。
- 缓存记录受当前 Windows 用户的 DPAPI 保护，绑定目录、可信清单、128 位文件身份、大小、时间、文件 USN 及变更日志代次。校验使用同一个只读句柄，并拒绝与写入／删除者共享，避免活动映射写入期间 USN 合并造成误命中。每次仍校验清单、枚举完整目录，并检查缺失、多余文件和链接。
- 只有具备可靠变更日志的本地 NTFS 文件可复用校验结果。ReFS、网络盘、元数据不可用或缓存无效时继续完整计算哈希。发现损坏或正在写入的文件时拒绝加载。
- 回退日志新增 `RIFE realtime fallback` 与丢帧、音画差、刷新率、倍率和模型等指标，不包含媒体 URL 或令牌。

## 真实播放验证

环境为 Windows、RTX 4090、驱动 616.64，显示器为 3840×2160／240 Hz。使用真实 H.264 10-bit、1920×1080、23.976 fps SDR 动画，实际生产 Qt Player、固定 libmpv、私有 VapourSynth R79／TensorRT、gpu-next／D3D11、默认画质着色器及 WASAPI 音频输出。

## 回归与验证范围

- NTSC 倍率、低刷新率正常省略、两个方向的刷新率切换及随后真实额外丢帧保护均有回归测试。
- 同大小写入并恢复修改时间、关闭后的映射写入、活动映射反复写入、损坏缓存记录、缺失／多余文件及其他原扩展校验回归均通过。
- 原生快速探测入口与独立完整探测入口、异步取消和运行库隔离有回归测试。
- 播放测试涵盖本机默认画质、1080p 23.976 fps 和三档模型；不代表所有 GPU、所有格式、4K 输入或 120/240 fps 都能实时运行，也没有与 SVP 做画质或延迟的等条件比较。
- 未在本地 Mac 真机重新测试播放；Mac 构建与打包检查记录在发布清单。现有 Mac 播放流程不受 Windows 校验缓存和保护分支影响。
