# 2.6.0 音量、首页观看进度与播放退出预览验证

本轮仍是本地预览，未发布 2.6.0，未合并 PR #5。使用独立测试配置，未修改已安装播放器的账号或音量。

## 音量规则与验证

用户确认首次音量应为 100。此前的单位换算修复保留了已写坏的旧值，因此升级预览第一次播放仍可能显示 0。本轮加入独立音量记录：没有新记录时将旧版 0／缺失／非法值恢复为 100，旧版非零值保留；初始化后，包括主动设为 0 在内的手动音量都会记住。存储写入失败也不能阻止播放或音量调节。

- `test_mpv_volume_preferences.js` 5 项通过。旧实现首先在迁移用例失败；存储异常用例也先复现播放加载被中断，再修复通过。
- 真实客户端、QWebChannel、libmpv 和本地静音 WAV：连续四次独立进程启动，恢复值依次为 100、100、37、0，进程正常退出码均为 0。
- 首次测试配置明确预置旧 `volume=0`，后续复用同一隔离 localStorage；并非只测试干净配置。
- 本轮重启通过 `SystemComponent.exit` 正常退出；历史实按红叉／Alt+F4 音频验证见前一份报告，本轮结果不能替代视频窗口关闭验证。

数据：[四次进程重启](data/2026-10-13-volume-v2-restart.json)。

## 首页观看进度

海报右上角新增红色「未看」，剧集按用户指定文案显示「观看进度：8/12」，大图说明也显示相同数字。有剩余未看集数的剧集显示红标，全部看完则隐藏；电影只显示观看状态。没有可靠数据时不猜测数字或强行标记。

首页先展示已有海报，然后最多四部剧并行读取各自的总集数和已看集数；不下载完整剧集目录。切换页面或媒体库会取消旧请求，播放返回首页会清理缓存并重新读取。

真实 Emby 数据中，曾出现作品汇总未看数与 Episode 查询结果不一致，所以不采用「RecursiveItemCount 减 UnplayedItemCount」。本轮调用发行代码 `HomeData.loadWatchProgress` 只读查询线上服务器，抽样结果为 6/10、40/328、7/58、36/36；分别与独立查询的未看集数核对，相加等于总集数，没有写入观看进度。

查询保留缺失／虚拟剧集排除的兼容参数，但当前服务器没有证明支持这些过滤参数。本轮验证的分母是它返回的 Episode 记录总数；未验证含虚拟未来集的其他服务器行为。

数据：[线上只读抽样](data/2026-10-13-home-progress-readonly.json)。UI 截图使用可重复的模拟媒体资料，不是线上账号截图。Chrome 检查包含响应式尺寸、缩小动态效果、观看状态刷新和触控；原生 QtWebEngine 回归在下方补充。

## 视频播放退出

已在未修复客户端复现：本地 Y4M 视频画面显示、播放位置递增后，调用退出接口，12 秒内进程仍不退出；本地 WAV 音频正常退出。原生 `CLOSE_WIN` 路径也复现未退出。测试位于 `tests/test_playback_exit.cjs`，明确检查进程退出码而非窗口隐藏。

退出改为 Windows 专用异步流程：强制 Alt+F4／CLOSE_WIN 交给宿主退出，停止当前媒体后异步确认 idle-active 和 current-vo 已释放，再恢复显示模式、窗口状态及屏保，结束应用事件循环。右上角红叉保留托盘偏好；非托盘关闭先拦下系统窗口销毁，进入同一清理流程。

退出等待期间禁止新媒体加载，屏蔽播放器控制、配置回调、调试信息及全屏同步的阻塞式 MPV 调用。重复退出请求去重；异常超时不触发「播放失败／转码重试」对话框，保留宿主窗口和退出重试通道。没有改变任意第三方脚本直接执行原始 mpv quit 的既有行为。

最终构建实际进程回归中，API 退出、CLOSE_WIN、Alt+F4 绑定、并发控制退出、空闲退出五项均正常结束，退出码 0，用时依次为 679、676、688、745、415 毫秒。并发控制包含暂停、跳转、调音量、切全屏和重复退出。数据见[播放退出回归](data/2026-10-13-playback-exit.json)。

本轮通过原生 MPV 按键绑定及宿主 API 投递事件，播放本地 Y4M；未将它表述为物理键盘 SendInput 或生产媒体实播。Windows Computer Use 初始化两次均返回 `failed to write kernel assets`，因此没有进行本轮实际键盘／红叉点击验收。

## Windows 完整回归

最终产品源码完成构建与部署后，CTest 全套 84 个目标中 83 个首次通过；首页界面目标在 Qt 页面尚未出现时达到 12 秒启动上限。将该测试的启动等待统一为其他原生 UI 测试使用的 30 秒后，单独复测通过（13.11 秒），累计 84 个目标均已验证通过。未改动业务行为来规避该超时。

Qt 内部仍有 7 个既有跳过：2 个需要独占桌面指针的吸附用例、3 个真实指针用例、1 个要求显示器工作区小于全屏的旧无边框最大化用例，以及 1 个需要私有 RIFE 运行时的探测用例。此前实际吸附验证记录仍见[窗口预览报告](2026-10-13-window-controls-preview.md)；不能把 CTest 目标通过理解成这些用例本轮也执行了。

新增音量偏好 5 项单测通过；首页的 QtWebEngine 测试包含红标、精确文案、异步取消、返回刷新、响应式尺寸和缩小动态效果。
