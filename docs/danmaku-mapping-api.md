# 共享弹幕自动匹配：客户端接入说明

协议版本：v1，2026-10-09。服务端为 NAS 上的 Tigerest 弹幕网关。

## 要实现的体验

用户把原视频第 3 集手动选到正确弹幕后，第 4、5……集自动沿用；第 8 集重新手动选择，则从第 8 集开始使用新的对应关系。换季重新识别。规则由服务器持久保存，同一网关下所有客户端共享。

本次已实现服务器接口；客户端必须按下文接入才能使用。原来的 `/api/v2/*` 接口保持兼容，但仅调用旧接口不会建立或读取共享规则。

## 一个接口，两种调用

`POST /api/tigerest/v1/danmaku`

- 网关地址沿用现有配置，例如 `http://nas.tigerest.top:18443`；LAN 联调可用 `http://192.168.5.150:18443`。
- `Content-Type: application/json`，UTF-8，最大请求体 16 KiB。
- 建议连接超时 5 秒、总超时 35 秒。服务器该接口总期限 30 秒，上游单次请求最多 12 秒。
- 只向自家网关发送该协议；第三方/官方服务器继续使用原有接口。

### A. 开始播放时读取共享规则

不需要写入令牌，也不需要预先知道弹幕 ID：

```json
{
  "source": {
    "title": "葬送的芙莉莲",
    "season": 1,
    "episode": 4
  }
}
```

命中时，服务器直接返回对应集的弹幕。不再单独请求 `/api/v2/comment/...`。

### B. 用户手动选中剧集时，顺带保存校准

替代此次原有的 GET 弹幕请求，不新增一趟上报请求。附带请求头：

```text
Authorization: Bearer <网关共享映射写入令牌>
```

```json
{
  "source": {
    "title": "葬送的芙莉莲",
    "season": 1,
    "episode": 3
  },
  "selection": {
    "bangumiId": "17617",
    "episodeId": "176170003"
  },
  "comment": {
    "withRelated": true,
    "chConvert": 0
  }
}
```

`source` 必须是**当前原视频**的信息；`selection` 才是用户选中的弹幕库。不要把 `source` 改写成搜索结果的作品名或集数，否则无法为原视频后续集数复用规则。即使原视频第 3 集对应弹幕第 5 集，也应提交 source.episode=3 和真正选中的 episodeId，偏移由服务器计算。

令牌对应服务器 `config.json` 的 `mappingWriteToken`，与弹弹play AppSecret 完全独立。由 NAS 管理者给受信任的客户端配置；不要硬编码进公开发行包或写入日志。无令牌客户端仍可读取共享结果，手动取弹幕则回退旧 GET 接口（不能保存共享规则）。

## 请求字段

| 字段 | 必填 | 含义 |
|---|---|---|
| source.title | 是 | 原作品标题，1–200 字符；使用媒体元数据的作品名，不要用带集数的整段文件名 |
| source.season | 是 | 原视频季度，整数 1–1000；拿不准季度时走原有识别流程，不要统一猜成第 1 季 |
| source.episode | 是 | 原视频本季集数，整数 1–10000 |
| source.edition | 否 | 剪辑/编号版本标识，最多 100 字符，默认空串；分集方式不同的版本需区别，不能放用户/设备 ID |
| selection.bangumiId | 手动时 | 搜索结果/剧集列表所属作品 ID，字符串；支持数字作品 ID 及 `tmdb-...` ID |
| selection.episodeId | 手动时 | 用户选中的弹幕库 ID，建议十进制字符串，也接受安全整数 |
| comment.withRelated | 否 | 布尔值，默认 true |
| comment.chConvert | 否 | 整数 0/1/2，默认 0，沿用原接口含义 |

有 `selection` 就表示手动校准，因此**只有明确的用户选择操作才能带 selection**。哈希匹配成功、自动搜索命中、读取历史成功、共享规则命中均不能冒充手动选择写回。

服务器对 title/edition 做 NFKC、首尾空白删除、连续空白合并和大小写规范化；不做作品别名猜测。自动请求和手动请求必须采用同一套 source 构造逻辑。字段名不接受拼写变体或未知字段。

## 响应及加载方式

命中（HTTP 200，示意数据）：

```json
{
  "success": true,
  "matched": true,
  "match": {
    "origin": "shared",
    "bangumiId": "17617",
    "animeTitle": "葬送的芙莉莲",
    "episodeId": "176170004",
    "episodeNumber": 4,
    "episodeTitle": "第4话 灵魂长眠之地",
    "seasonId": null,
    "anchorSourceEpisode": 3
  },
  "danmaku": {
    "count": 1,
    "comments": [{ "p": "1,1,16777215,u", "m": "示意弹幕" }]
  }
}
```

- `origin` 为 `manual`（本次手动校准成功）或 `shared`（沿用共享记录）。
- `danmaku` 就是原弹幕 GET 接口的完整 JSON 对象，交给现有弹幕解析/加载函数。
- `match.episodeNumber` 是目标弹幕目录的集数，不是原视频的集数；`match.seasonId` 是上游内部季度 ID，与 source.season 不同。
- `X-Cache: HIT/MISS/COALESCED` 只描述弹幕内容缓存。手动请求即使命中内容缓存，仍会保存校准记录。
- 播放项已切换时丢弃旧响应，避免把上一个视频的弹幕加载到当前视频。

未命中也返回 HTTP 200：

```json
{ "success": true, "matched": false, "reason": "no-mapping" }
```

reason 可为 `no-mapping`（无当前或前置校准）、`episode-unavailable`（目标集不存在或编号有歧义）、`anchor-changed`（上游已删除锚点/修改编号或季度）。此时继续客户端原有匹配和搜索流程，不将其当作网络故障。

## 客户端接入位置

1. 开始加载弹幕时，在本机历史复用、哈希匹配及标题搜索**之前**，用原视频元数据调用 A。命中直接加载 danmaku；未命中/请求失败继续原有流程。每个新播放项都查共享规则，避免长期保存旧推断而看不到其他客户端的校准。
2. 手动选择事件需要保留搜索结果的 bangumiId，并在载入选中弹幕时调用 B。成功后直接加载返回的 danmaku，不再重复调用原来的弹幕获取函数。
3. B 失败时可用选中的 episodeId 调用原 GET 接口加载弹幕，同时提示“弹幕已加载，但共享匹配未保存”；没有成功响应不要显示保存成功。不要为了重试而把自动匹配结果写成手动规则。
4. 建议显示“来自共享匹配”并保留手动纠正入口。再次手动选择会更新当前集开始的分段。

现有 Lua 客户端可在 `auto_load_danmaku` 前接入 A，在 `load-danmaku` 的用户选集事件接入 B；目前该事件还需要从剧集列表传入 bangumiId。本次没有修改客户端，需客户端开发完成接入并打包。

## 分段行为与边界

- 同作品、同季度、同 edition，找不晚于当前集数的最近一次手动校准。第 3 集校准不会反推第 1、2 集。
- 第 3 集映射到目标第 5 集，则原第 4 集对应目标第 6 集。根据官方剧集列表查实际 ID，绝不对 episodeId 加减。
- 第 8 集再次校准，原第 3–7 集继续使用前一个分段，第 8 集及以后使用新分段。更晚集数已有的手动分段仍保留；重新校准第 3 集不会抹掉第 8 集记录。
- 原季度和上游季度均隔离，不跨季推算。特殊篇、非整数集数、重复编号没有安全对应时走原有流程。
- 相同分段有多人更正时，最后成功保存的校准生效。分集方式不同应使用不同 edition。
- 映射保存在 NAS SQLite 中，不随弹幕缓存过期或服务重启消失。映射成功不代表内容永久离线可用，内容过期后仍需访问上游。

## 错误处理

错误体为 `{ "success": false, "errorMessage": "..." }`。

| HTTP | 含义/客户端处理 |
|---|---|
| 400 / 413 / 415 | 参数错误/请求过大/不是 JSON；修正调用 |
| 401 | 手动写入令牌缺失或错误；可回退旧接口取弹幕 |
| 404 / 405 | 服务不支持新协议或方法不对；旧服务回退原流程 |
| 422 | 手动选项不属于该作品的唯一正常剧集；特殊篇等回退旧 GET |
| 429 | 本地限流或上游预算耗尽；遵守 Retry-After，避免立即重试 |
| 502 / 504 | 上游失败/超时；不要记录为共享校准成功 |
| 503 | 未配置写入令牌、上游忙、记录容量满或服务关闭；允许回退 |

服务端现有日/月预算、限流及固定上游规则继续有效。只开放本说明的参数，不接受任意 URL，也不把 source 或写入令牌发给弹弹play。

上游季度及剧集字段依据[弹弹play官方接口规范](https://api.dandanplay.net/swagger/v2/swagger.json)。
