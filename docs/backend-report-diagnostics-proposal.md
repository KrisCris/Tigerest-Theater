# 报错日志附件：后端开发对接清单

2026-10-08 的接口提议，保留作开发记录。2026-10-09 已收到后端完成后的正式契约；当前接入以 [community-api.md](community-api.md#报错诊断日志附件2026-10-08) 为准，下面的建议不再代表待开发项或最终字段。

目的：用户提交报错时自动附带相关诊断日志，让管理员在同一条报错中查看，无需让用户另行运行 ADB 导出脚本。

## 1. 保留现有报错接口

`POST /reports` 的请求、响应、权限、限流和幂等规则保持兼容。`context` 仍只接收现有诊断字段，日志走独立附件接口。报错提交成功后，再上传附件；日志失败不能导致已经提交的报错被当作提交失败，也不能重复创建报错。

客户端会修正 `context.platform`：优先采用原生平台信息，规范值为 `Windows`、`macOS`、`Android`、`Linux`、`FreeBSD`；无法确定时省略。后台应显示此客户端字段。`context.positionSeconds` 保持数值秒：用户填写“12 分 30 秒”，客户端提交 `750`。

## 2. 新增单个日志附件上传

建议 `PUT /reports/{reportId}/diagnostics`，仍使用现有三个 Emby 身份头，不使用媒体 Item 认证头。必须验证报错属于当前用户；他人或不存在的报错返回 404。一条报错最多一个附件，不能替换已有附件。

Content-Type 为 `application/json`，示例：

```json
{
  "clientRequestId": "为附件生成并在重试中复用的 UUID",
  "capturedAt": "2026-10-08T08:00:00Z",
  "truncated": true,
  "logText": "已脱敏的 UTF-8 诊断信息与相关日志……"
}
```

- 白名单只接受以上字段。`capturedAt` 是合法 UTC ISO 8601；`truncated` 是布尔值；`logText` 必须非空。
- 解码后的 `logText` 最多 1 MiB，按 UTF-8 字节计算；JSON 请求体上限建议 8 MiB，以兼容字符转义。只接收纯文本，不接收 ZIP、HTML 或任意文件路径。
- 首次成功返回 201；同用户、同报错、同附件 `clientRequestId` 和相同内容重试返回 200。相同 ID 改内容返回 409 `IDEMPOTENCY_CONFLICT`；该报错已有其他附件返回 409 `DIAGNOSTICS_ALREADY_EXISTS`。
- 客户端必须只抓取一次日志快照，生成一次附件 UUID；网络重试不能重新抓取变化后的日志。
- 使用现有 `{data,requestId}` / `{error,requestId}` 响应封装。失败建议区分 `DIAGNOSTICS_TOO_LARGE`、`DIAGNOSTICS_STORAGE_UNAVAILABLE` 和权限错误；限流使用 429 与 `Retry-After`。沿用报错的速率限制，成功附件的幂等重试不重复占新额度。

成功响应示例：

```json
{
  "data": {
    "diagnostics": {
      "id": "附件 UUID",
      "createdAt": "2026-10-08T08:00:01Z",
      "bytes": 24000,
      "truncated": true,
      "availability": "available"
    },
    "replayed": false
  },
  "requestId": "请求 UUID"
}
```

附件记录关联 reportId 和实际作者。保存附件及元数据需原子完成，失败不能留下看似可下载的空附件。

## 3. 私有读取与管理后台

- `GET /me/reports`、`GET /me/reports/{reportId}` 和修复消息中的 report 可增加 `diagnostics` 元数据（无附件时为 null），不要把日志正文放进列表或通知。
- 建议 `GET /me/reports/{reportId}/diagnostics` 供本人下载；后台增加对应管理员下载入口，沿用后台已有登录、管理员权限和局域网访问限制。附件即使知道 UUID 也不能公开下载。
- 下载返回 `text/plain; charset=utf-8`，固定生成安全文件名与 `Content-Disposition: attachment`，并设置 `Cache-Control: no-store`。后台预览必须按纯文本转义，不能执行日志中的 HTML。
- 报错详情显示“诊断日志”、上传时间、大小、是否截断，以及“查看／下载”。平台取 `report.context.platform`，不能用服务端操作系统代替。
- 媒体下架后，本人和管理员仍可访问已有报错及其附件；报错的修复、通知和已读逻辑保持兼容。

## 4. 脱敏、存储与保留

- 客户端上传前去除登录 Token、认证头、密码、播放 URL 的签名／敏感查询参数、本地绝对路径和私人账号信息。当前普通日志脱敏不能直接视为足够，需要覆盖 JSON、HTTP 头、URL 查询参数、大小写变化及 URL 编码。
- 服务端对已知敏感格式再做脱敏；不得把附件请求正文写入访问日志或调试日志。附件放私有存储区，不能放到可直接访问的静态文件目录。
- 保留状态码、组件错误、播放器状态、字幕／弹幕匹配信息等排查线索。可增加管理员下载审计，但审计不保存正文。
- 建议正文保留 30 天，期限可配置；到期删除正文并把元数据标为 `expired`。下载过期附件返回 410，报错和修复说明继续保留。保留轻量幂等记录，重试不会重新上传已过期内容。

## 5. 客户端后续对接流程

报错窗口默认勾选“附带诊断日志”，显示已脱敏说明，允许用户取消。仅收集当前账号配置的最近约 10 分钟日志，最多 1 MiB；必要时附上一启动末尾的故障记录，并标明截断。Windows／Mac 从当前配置的应用日志抓取；Android 需要先补充应用内的有界诊断日志记录，不能依赖用户电脑 ADB，也不能抓取其他应用日志。

提交后先取得 reportId，再上传固定日志快照。成功显示“报错已提交，诊断日志已附带”；附件失败显示“报错已提交，日志上传失败”，提供单独重试日志。日志无法读取或用户取消附带时，仍可正常提交报错。退出登录／切换账号／取消操作要停止待发请求并清除内存中的日志快照。

## 6. 后端验收用例

1. 本人上传／下载成功，其他用户和未登录请求不能访问，后台遵循现有管理员权限。
2. 首次 201、相同内容重试 200、相同 ID 改内容 409、同报错第二个附件 409；成功重试不重复扣额度。
3. 无效 UUID、时间、类型、空文本和超出 UTF-8 字节上限均拒绝；非白名单字段不接受。
4. 模拟存储失败，报错仍存在且没有假成功附件；客户端只重试附件。
5. 带伪造 HTML、路径和各种 Token 格式的日志不能执行内容、越权读取或泄露秘密；访问日志中不出现附件正文。
6. 列表及通知只带元数据；媒体失效后附件权限正确，现有修复通知及已读流程不受影响。
7. 到期清理正文，下载返回 410，报错与修复说明保留，旧请求重试不会复活附件。

完成后请把最终路由、字段、状态码、大小限制、保留期限和权限规则写入 `community-api.md`。上述名字可按后端规范调整，但客户端接入需要最终契约。
