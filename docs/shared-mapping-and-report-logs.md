# 共享弹幕与报错日志接入

本次客户端预览沿用 2.4.4 版本号，包含此前的平台识别与分秒输入修正。正式发布仍以 GitHub 已发布版本为准。

## 共享弹幕

开始播放时，客户端先向自己的 NAS 网关查询当前作品、季和集的共享规则。命中直接加载返回弹幕，并提示“来自共享匹配”；未命中、接口不可用或季度未知时，继续原有匹配与手动搜索。

只有用户明确手动选择作品及集数时才保存校准。保存使用原视频信息和选中的真实弹幕 ID，由后端计算后续对应关系；客户端不递增弹幕 ID。其他客户端校准后，新播放项会重新查询共享规则。第三方弹幕服务继续使用原接口。

保存校准需要 NAS 管理者提供 `mappingWriteToken`；读取共享匹配无需令牌。客户端默认不包含写入令牌。

- Windows/macOS：在当前播放器配置的数据目录创建 `private/danmaku-mapping-authorization.txt`，只写一行 `Authorization: Bearer <令牌>`。Windows portable 的位置为播放器目录下 `data/profiles/<配置ID>/private/`；普通 Windows 配置位于 `%LOCALAPPDATA%/Tigerest Theater/profiles/<配置ID>/private/`。文件权限限制为当前用户，勿放入公共 MPV 配置、源码、安装包或设置导出。删除该文件即可取消写入权限。
- Android：播放页“弹幕 → 配置共享匹配写入令牌”，输入并保存；留空保存可清除。令牌保存在应用私有数据中，不进入网页设置或导出内容。

未配置令牌时，手动选择仍可正常加载弹幕，但不保存共享规则。已配置令牌而共享保存失败时，客户端按选中的 ID 加载旧接口弹幕，并提示“弹幕已加载，但共享匹配未保存”。

## 报错日志

报错窗口默认勾选“附带诊断日志”，用户可以取消。发生时间按“分钟”和“秒”填写，接口仍提交秒数。

日志采集仅覆盖当前登录会话与当前客户端配置中、最近约 10 分钟的应用记录，最多 1 MiB。应用在记录边界先脱敏，再向网页桥接返回一次快照；账号与配置切换时隔离记录。敏感字段、认证头、编码/转义 URL、私人账号信息及本地绝对路径会删除或替换，不上传整个设备日志。Android 使用应用内日志，无需 ADB。此前启动的日志不会混入当前会话；日志不可用时照常提交报错。

客户端先提交报错，再独立上传日志。报错成功而日志失败会保留成功状态，并提供“重试日志附件”；重试使用同一份快照和同一个附件 UUID，不再次提交报错。限流按服务端等待时间执行；退出、取消或切换账号会中止待发请求并清除快照。

附件仅报错本人和后台所有者可读取，默认保存 30 天。报错记录和修复结果按后端契约继续保留。

接口的最终字段、限制及错误码见 [community-api.md](community-api.md) 和 [danmaku-mapping-api.md](danmaku-mapping-api.md)。
