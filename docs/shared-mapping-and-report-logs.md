# 共享弹幕与报错日志接入

当前客户端候选为 2.6.0，包含公共评论 v2、普通大河登录用户的共享绑定保存、动态密码规则、头像同步和音量记忆修复。后端新能力已经上线；2.6.0 客户端仍等待窗口功能预览验收，尚未正式发布。普通用户见 [公共评论教程](https://github.com/Tigerest/Tigerest-Theater/wiki/Community)与[弹幕教程](https://github.com/Tigerest/Tigerest-Theater/wiki/Danmaku)。此前实现验证见 [2026-10-12 记录](reports/2026-10-12-community-v2-client-validation.md)，新后端联调见 [2026-10-13 生产记录](reports/2026-10-13-community-production-validation.md)。

## 共享弹幕

开始播放时，客户端先向自己的 NAS 网关查询当前作品、季和集的共享规则。命中直接加载返回弹幕，并提示“来自共享匹配”；未命中、接口不可用或季度未知时，继续原有匹配与手动搜索。

只有用户明确手动选择作品及集数时才保存校准。保存使用原视频信息和选中的真实弹幕 ID，由后端计算后续对应关系；客户端不递增弹幕 ID。其他客户端校准后，新播放项会重新查询共享规则。第三方弹幕服务继续使用原接口。

大河用户登录 Emby 后自动取得共享绑定写入权限，无需管理员 JSON 或额外令牌；读取共享匹配仍匿名。客户端通过能力接口核验可信 ServerId，并在手动保存时使用当前 Emby 会话。退出或切换账号会撤销旧授权。外服 Emby 凭据和独立公共评论账号的 Bearer 不用于共享绑定。

旧服务的映射能力接口返回 404 时，仅对已核验的大河身份使用客户端原来保存的私有授权；新发行包不内置该凭据，也不要求新用户配置。401、403、503 不触发旧令牌回退。

当前会话无法保存时，手动选择仍可加载所选弹幕，并明确提示“绑定未保存”。收到网关 429 时按 `Retry-After` 等待，不通过旧弹幕接口绕过；同一 NAS 的局域网和 DDNS 地址共用等待时间，切换播放项也保留等待。

## 公共评论与账号

大河账号进入公共评论时自动登录；其他 Emby 服务器的用户使用独立评论账号。支持注册、登录、退出和修改密码。Windows 使用系统凭据管理器，macOS 使用 Keychain，Android 使用 Keystore 加密保存；安全存储不可用时明确提示仅本次登录有效。

2026-10-13 增量按能力接口决定密码规则：新服务为 8–128 个 Unicode 码点，旧服务仍为 12–128；注册/改密直接显示范围，不限制已有密码登录。禁止控制字符，不裁剪密码中的空格。自建用户必须登录评论账号才能查看或发送，退出后清除旧评论、回复预览和图片对象。

新服务支持头像同步时，自建用户每次发言前从自己的 Emby 读取本人头像，在本机生成最多 128×128、256 KiB 的 PNG，并计算实际字节 SHA-256。评论成功后才按后端要求上传；失败只重试头像，409 不强制覆盖，429 单独等待。明确无头像才清除旧图，读取失败保留旧图。大河用户的头像由后端同步。各处头像均由中央服务鉴权读取，URL 不附加令牌；旧服务不发送新增字段或上传请求。

后端目前已宣告 8 字符密码下限和头像策略，并通过真实 Windows 原生桥完成注册、改密旧会话撤销、主评论／回复、头像上传／免上传／更换／清除、匿名拒绝与版本冲突生产验证。头像来源使用本地 Emby fixture，不代表任意自建 Emby 实测；细节与未测范围见 [生产联调记录](reports/2026-10-13-community-production-validation.md)。[头像与密码增量记录](reports/2026-10-13-community-avatar-password-validation.md)保留此前后端尚未部署时的历史结果。

公共讨论按可靠的 TMDB 作品及播出季集关联。缺少可靠编号、未知集序、DVD 或合并集时不猜测。大河用户可切换本服评论并保留私人报错；大河消息使用 v1 统一列表避免重复，外服仅展示公共消息。跨服跳转只接受自己媒体库中的唯一匹配，无法定位时仍可查看公共讨论。

2026-10-09 的桌面与 Android 修订取消日期确认。先确认作品与季度，唯一的规范化单集标题匹配优先于集数；标题缺失或译名不同则按集数匹配。查询失败不否决其他已有结果，相同来源和单集 ID 的重复记录去重，仍有多个等价候选时保留手动选择。OSD 显示选中的作品、集名和手动纠正提示，片头片尾不作为正片候选。具体例子与脚本评估见 [弹幕匹配说明](reports/2026-10-09-danmaku-credit-matching.md)。

首播日期不会选中另一集，也不会因日期差异拒绝相同集号。对应作品与季度内，唯一的单集标题可识别连续编号与分季编号；其他编号差异交给共享规则或手动选择，不再按日期猜测。共享匹配接口、优先级和手动保存条件不变，后端无需为此修改。

例如 2026-10-09 播放《转生成为魔剑了》S02E02 时，Emby 首播日期为 2026-10-15，恰好等于弹幕目录第 3 集的日期，旧桌面代码因此请求了 177890003。修订后按第 2 集编号选择 177890002，不受该日期影响。另一次查询《我推的孩子》时，第 1 集两边日期相差 26 天；旧日期限制会拒绝匹配，桌面新策略不会仅因此拒绝相同集号。

Mac 补充修订将作品名中的“第二期”“第2期”识别为第二季，并保留季度冲突保护。Android 同步使用主分支无日期策略，本次 Mac 修订不改动 Android 代码。切换影片时丢弃旧查询结果，已保存的手动纠正和共享匹配优先使用。

## 报错日志

报错窗口默认勾选“附带诊断日志”，用户可以取消。发生时间按“分钟”和“秒”填写，接口仍提交秒数。

客户端说明最低长度已降至 3 字，仍最多 2000 字。客户端直接提交 trim 后的真实文本，不补足到 10 字。2026-10-09 已在局域网 18443 生产接口验证：2 字拒绝，3 字提交成功，platform 保存为 Windows，真实日志附件上传及下载成功。校验范围与联调结果见 [后端字数限制同步清单](backend-report-minimum-length.md)。

同日 Android 新 APK 已在独立调试包的真实 WebView 中验证 3 字提交、2 字本地拒绝、分钟/秒转换和 Android 平台标记，并验证真实应用日志及 MPV 404 回调的采集、账号隔离与脱敏。设备界面和上传重试检查使用本地 fixture，没有向生产接口投递 Android 测试报错。

日志采集仅覆盖当前登录会话与当前客户端配置中、最近约 10 分钟的应用记录，最多 1 MiB。应用在记录边界先脱敏，再向网页桥接返回一次快照；账号与配置切换时隔离记录。敏感字段、认证头、编码/转义 URL、私人账号信息及本地绝对路径会删除或替换，不上传整个设备日志。Android 使用应用内日志，无需 ADB。此前启动的日志不会混入当前会话；日志不可用时照常提交报错。

客户端先提交报错，再独立上传日志。报错成功而日志失败会保留成功状态，并提供“重试日志附件”；重试使用同一份快照和同一个附件 UUID，不再次提交报错。限流按服务端等待时间执行；退出、取消或切换账号会中止待发请求并清除快照。

附件仅报错本人和后台所有者可读取，默认保存 30 天。报错记录和修复结果按后端契约继续保留。

接口的最终字段、限制及错误码见 [community-api.md](community-api.md) 和 [danmaku-mapping-api.md](danmaku-mapping-api.md)。
