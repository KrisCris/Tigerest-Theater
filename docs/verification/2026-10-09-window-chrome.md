# Windows 自绘顶栏验证记录

## 已批准的行为

Windows 全局使用自绘顶栏：窗口及最大化模式固定 36 个逻辑像素，全屏时隐藏且不占空间。顶栏由 Qt 绘制，包含品牌、最小化、最大化／还原、关闭；支持拖动、双击最大化及边缘／四角缩放。作用于连接页、登录页、首页、媒体库、作品页及窗口播放。Android 无桌面标题栏，macOS 保留原生窗口边框。

## 实现

`WindowChrome.qml` 注册到现有 Konvergo QML 模块。Windows 主窗口使用 FramelessWindowHint，WebEngine 和视频视口避开 36 像素顶栏；全屏时恢复完整视口。原 F11、Alt+Enter、窗口状态保存、关闭到托盘和托盘还原逻辑继续使用原接口。

Qt 6.9.3 的无边框最大化没有原生 WS_MAXIMIZE 状态，因此拖动最大化窗口前显式还原原尺寸，并按鼠标在顶栏的相对位置放置窗口，再启动系统移动。

GPU-Next 子 HWND 会遮住 QML 的鼠标区域，窗口模式下视频左／右／下保留 5 像素缩放边，边缘覆以深色以免露出底层网页。最大化和全屏没有视频缩放边。顶栏和缩放边的层级高于网页，页面切换无需重复注入。

## 检查范围

先运行新原生用例确认缺少 WindowChrome 时失败，再实现组件。使用同次 PowerShell 内的 `Enter-TestEnvironment.ps1` 完成运行库及两个平台插件预检；所有测试使用独立窗口或临时配置，未改动正式安装及其设置。

- `test_window_chrome`：固定顶栏、全屏隐藏及恢复、最大化使用屏幕可用区域、最大化／还原／最小化／关闭按钮、双击、8 个缩放区域与视频视口分离、最大化拖动还原位置、播放边缘遮罩、关闭组件后恢复完整视口。
- `test_windowmanager`、`test_windowmanager_opengl`：窗口及播放全屏状态、原生视频宿主生命周期、Windows 合成回归。
- `test_webengine_startup`：真实应用的软件及 D3D11 启动，生产同步补丁执行。
- `test_server_onboarding_webengine`：真实应用连接及登录页夹具。

上述 5 项 CTest 均通过；额外的 `test_home_gallery_webengine` 也通过，合计 6 项。后者重新验证首页布局、入场顺序、作品切换、缩放窗口及减少动态效果。原生组件截图来自独立窗口夹具，不能当作真实 Emby 页面截图。

独立 Windows 预览连接真实服务器，首页、作品页、媒体库网页视口均为 1280×684（主窗口高 720，顶栏占 36）；全屏为 2560×1440，退出后恢复 1280×684。首页加载 4 个入口和 24 部作品，原底栏隐藏；窗口模式从详情／媒体库返回首页不会再次强制全屏。预览保持打开，便于用户查看自绘顶栏。一次导航检查在作品页仍加载时请求返回首页，导致检查超时；等待作品页完成后重测全部跳转通过，未为该夹具时序问题更改产品代码。

界面自动化的 node_repl 内核初始化失败，重置后仍返回“failed to write kernel assets / 系统找不到指定的路径”；没有完成完整 OS 鼠标拖拽自动回放，也未在本批执行真实媒体播放。夹具验证了拖动所需的尺寸／位置还原和宿主几何；Windows 11 的最大化按钮悬停 Snap 布局不在本次实现中。
