# 2.5.0 播放控制与移动安全区验证（2026-10-09）

本次实现包含 Android 系统方向锁、防误触、原生选集，以及 Windows/macOS UOSC 的 Emby 队列接入。正式安装目录和设置未修改，手机使用独立调试包。

## 切集边界

- Emby 使用 `PlaylistItemId` 标识队列中的一次播放；相同媒体 Id 可以重复出现。原生控件只接收队列身份、媒体 Id、名称、季数和集数，不接收文件路径、播放 URL 或全部媒体元数据。
- `playbackstart`、原生 `playing` 与去重轮询同步队列，覆盖原生开始播放早于网页注册事件的情况。
- Emby 切集先解绑 `stopped`，等待旧播放器停止，再重新绑定并开始新集。Android 等待桥接停止回复；桌面等待原生 `stopped`，而不是只等待 mpv 接收命令。旧 Android 会话通知按 generation 丢弃。
- 原生播放错误没有桌面 `stopped` 信号时，错误处理不再对已经结束的文件重复停止。停止超时仍清理资源，后续播放可以恢复。

## 已执行检查

- Android JVM 单元测试 71 项通过；lint 0 错误、38 警告。调试和 release APK 均构建成功，release 延续现有签名并通过 16 KB native alignment 检查。
- 独立手机夹具验证防误触下的手势、返回与短按被拦截，长按解锁有效；Activity 重建保留锁和可见视频；直接上一集、下一集、选集；系统锁定横屏后换集及回浏览仍为横屏，重新开启自动旋转交还系统控制。夹具结束恢复真实网页、系统设置，并清空测试队列。
- **真实 Android 播放**：从 Emby 获取完整的 12 集队列，播放《凭你也想讨伐魔王？》第 2 集，实际点击上一集至第 1 集、下一集返回第 2 集，再通过原生选集切至第 3 集。各次原生与 Emby 队列身份、媒体 Id 和名称一致；视频可见、播放活跃，媒体容器仍挂载。
- Qt→libmpv→UOSC 夹具检查上一集、下一集、菜单选择、队列首尾边界、过期身份拒绝、清队列后回退普通文件列表；发行字体中的 `assessment` 渲染为单个有效 glyph。
- Node 播放生命周期回归覆盖 Android/桌面的停止等待、旧取消与新播放分离、原生错误后重播、超时后的资源释放和恢复、零音量及小数音量记忆。
- 首页 6 种安全区 geometry 与普通页面检查通过，状态栏、横屏挖孔和底部手势区避让，背景仍铺满窗口。键盘聚焦测试固定入场首帧，确认媒体库卡片与末张封面完整进入可见区域。
- Windows 使用本地 GPU-Next 和真实系统鼠标状态的独占夹具，验证约 3 秒隐藏、移动恢复；3 项通过。默认 CTest 不占用鼠标，独占检查需显式启用。

## 验证范围

夹具队列检查不能代替生产 Emby 播放，二者分别记录。Android 已执行上述真实切集；Mac 由发布 CI 构建和测试，尚未进行 Mac 实机播放。Android 15、x86_64 与实际 16 KB page-size 设备未做实机验证。最终构建 SHA、完整 CTest、包校验及 Mac CI 结果写入发布附件的 RELEASE-MANIFEST。
