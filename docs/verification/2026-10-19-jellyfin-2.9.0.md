### Windows 原生与集成

先完整阅读 [Windows 测试说明](../../dev/windows/TESTING.md)。按现有构建流程准备本工作区独立构建目录，再在**同一 PowerShell 调用**加载环境和运行 CTest：

```powershell
$ErrorActionPreference = 'Stop'
. ./dev/windows/Enter-TestEnvironment.ps1 -BuildDirectory './build-jellyfin-290'
ctest --test-dir ./build-jellyfin-290 --output-on-failure --timeout 180
if ($LASTEXITCODE -ne 0) { throw 'Jellyfin 2.9.0 CTest failed' }
```

`libmpv-2.dll`、RIFE bridge、Qt DLL、qwindows 与 qoffscreen 任一缺失都先修复，禁止直接启动测试 EXE。原生单项测试也要在同一调用里加载脚本。只对合适的单项策略测试设置 offscreen；可见窗口、WebEngine 与真实播放保持 Windows 平台。记录跳过项，不能把目标通过数写成所有用例都执行。

部署到隔离暂存目录后再测客户端，不覆盖已安装播放器，不继承真实登录配置。Qt 环境和资源路径按仓库脚本管理，不临时指向未部署的 WebEngine。

### Android 与 Apple

Android 使用 [现有构建脚本](../../android/build.ps1)，为本工作区选独立 ASCII junction，例如：

```powershell
./android/build.ps1 -AsciiWorkspace 'C:\A\tigerest-jellyfin-290-android' -Tasks testDebugUnitTest,lintDebug,assembleDebug
```

执行前确认目标不存在或已指向本工作区，依赖缓存可复用。验证 APK 内共享脚本与源码一致；JVM/lint/构建通过不等于 Android 真机播放通过。

AppleCore 在具备兼容 Swift 工具链的环境运行 `swift test --package-path apple/Core`。iPad/tvOS/macOS 的 Xcode 构建、原生 UI 和真机播放需要对应 Apple 环境，按 [iPad 安装说明](../apple/INSTALL.md) 和 [Apple TV 构建测试说明](../../apple/TV/README.md) 执行；Windows 上静态检查不得记成 Apple 构建或真机通过。
