# 共享弹幕与报错诊断验证

日期：2026-10-09，基于 `c9409015e77f9c7fcbf6e2fd5081a6c18d05310f`，分支 `codex/shared-danmaku-report-logs`。客户端仍为 2.4.4 预览，包含此前平台和分秒输入修正。

## 实现范围

- 桌面 Lua 与 Android：先查询共享映射，明确的手动选集携带原作品/季/集及真实 catalog/episode ID；完整响应直接加载。没有写入凭据及接口故障时保留原接口。凭据位于私有配置，未进入公共源码、网页设置或安装包。
- 同一播放中手动纠正会取消旧自动/历史匹配请求；桌面搜索菜单贯穿原播放标识并在换片时失效。取消了客户端递增不透明弹幕 ID 的历史推断。
- Qt 与 Android 在实际日志记录边界脱敏，限制当前配置/账号、最近十分钟、1 MiB UTF-8；支持编码/转义字段及 URL、认证头、私人账号/邮箱、绝对路径和非法字符。未导入前次启动记录。Qt 遵循现有日志级别，避免正常播放时额外写入被抑制的 mpv verbose 消息。
- 报错默认附带日志，可取消；只捕获一次并冻结快照与 UUID，先 POST 报错再 PUT 附件。附件失败不影响报错成功，单独重试；分别限流、取消并隔离账号，401/409 禁止继续复用。
- Portable 打包排除用户 data/profiles/logs，防止临时日志或私有校准凭据随安装包分发。

## 验证结果

Windows 全套 CTest **65/65 通过，129.09 秒**。每次原生测试均在同一 PowerShell 调用读取测试说明并加载 `dev/windows/Enter-TestEnvironment.ps1`，包括 MPV/RIFE/Qt 及 Windows/offscreen 插件检查。使用独立测试配置，没有改动用户正式版设置。

Android 最终构建成功：JVM **55/55**，Lint **0 错误、37 警告**，debug / androidTest / release APK 构建及原生库 16 KiB 对齐检查通过。正式签名预览 APK 已核验签名与原生库；不替换手机上的正式应用数据。

Android 16 真机的独立调试版验证通过：

- 真实原生日志桥接、作用域切换、脱敏、清除。
- 报错日志默认勾选、取消/不可读、报错成功后附件失败、同快照重试、独立限流、冲突和账号切换取消。
- 统一消息、修复通知、报错历史、8 个平台/UA 案例及分秒输入边界。
- 本地 720p H.264 播放夹具中的弹幕自动匹配、来源策略、缓存及迟到响应丢弃；弹幕重绘约 120 fps。此数值是 overlay 重绘计数，不代表视频补帧或实际运动帧率。
- 独立 HTTP 404 媒体：真实 MPV 错误回调进入应用日志，保留 404 线索并删除私人播放 URL。

Windows QtWebEngine 同时通过真实原生采集桥接验证及共享报错 UI 夹具。UI 夹具另用模拟采集器覆盖回调/Promise 双交付、异常与重试；它们不替代真实采集桥接证据。

有 RED→GREEN 证据：敏感字段/Unicode/编码 URL/路径、跨账号/配置日志、时间/字节限制、时钟回退、手动选择胜过迟到自动结果、旧搜索菜单不能校准新作品、Portable 排除私有数据。完整输出保存于工作树 `build/shared-integration-2026-10-09/`。

## 生产接口与验证边界

只读探测实际 LAN 网关：`POST /api/tigerest/v1/danmaku` 仅携带 source，无 selection/认证，返回 **200 / success=true / matched=false / no-mapping**，约 270 ms；匿名读取日志附件返回 **401**。

没有用真实 Emby 身份向生产创建报错、上传日志或保存共享规则。生产写入仍需真实账号与 NAS 管理者配置的 `mappingWriteToken` 验证；协议、失败及幂等流程由独立夹具验证。未进行 macOS、Android 15、x86_64 或 16 KiB 页设备实机测试。

初次 Android 界面夹具因手机锁屏/休眠而超时，用户解锁后全部重新通过。第一次 Windows ZIP 打包遇到正在运行的测试进程占用 Qt DLL，测试结束后重新打包；不把这些环境失败记为产品通过证据。
