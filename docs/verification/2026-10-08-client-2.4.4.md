# 2.4.4 本地试用验证（2026-10-08）

本次修改使用现有 `codex/mobile-layout-comments` 隔离工作目录，接口以用户提供的 `X:/community-api.md` 为准。没有发布正式版本或替换已安装的 Windows 播放器；安卓仅安装独立 debug 包进行验证。

## 客户端行为

- 收到的消息使用 `/me/messages?type=all`，包含回复和报错修复通知；单条及快照全部已读使用同一接口，保留快照之后到达的新消息。
- 电影、剧集、单集详情可提交问题；报错历史与详情分别使用 `/me/reports` 和 `/me/reports/{id}`。说明、修复结果按纯文本展示，媒体失效仍可查看修复内容。
- 报错与评论分别限流；网络失败重试复用提交 UUID。提交期间锁定输入，离开详情或切换账号清理草稿，迟到响应不能重建已关闭的私有界面。
- Android 顶栏换行后靠右。整排不足时保留消息、更新、头像及「更多」，二级菜单调用原按钮操作，保持原可见性、禁用状态及页面上下文。

## Windows 补帧故障

原日志显示 `os.add_dll_directory` 抛出 WinError 206，随后 mpv 禁用补帧滤镜。原因是图重建时重复注册 DLL 搜索目录且未调用 `close()`，累积搜索路径耗尽限制；并非单个目录过长，也不是性能统计保护触发。

修复给每个 VS 脚本实例建立目录注册租约：图释放后注销，注册或滤镜构建失败时回滚。清理栈与弱引用目标分离，避免自行保活。可信插件导入路径同时去重。性能不足仍只提示并保留补帧；滤镜加载或运行失败显示单独原因。既有 NVIDIA 扩展加入 2.4.4 兼容清单。

旧进程已经遗失的目录注册无法由新脚本追溯释放，因此安装更新后需要完全退出（含托盘）并重启客户端。
