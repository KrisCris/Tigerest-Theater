# 首页／媒体夹／详情转场触发延迟优化 · 2026-10-10

基线为 upstream `v2.5.2`（`977a480`）。本轮只改转场的准备方式，海报飞行、遮罩、首页飞出及入场的关键帧和时长保持不变。

## 2.5.2 点击卡顿的来源

1. **命中缓存仍重排整页副本。** 媒体夹和详情页的预热快照是整页 DOM 副本（含复制进 shadow 的全部样式表）。点击时它被移出隐藏容器、放入遮罩层，再同步恢复滚动位置；移动节点会丢弃布局，整棵副本在首帧前重新计算样式和布局。海报转场里这份副本透明度为 0，并不可见。
2. **未命中时点击同步复制整页。** 缓存失效后（滚动、悬停改动 DOM、轮播、图片加载）约 0.3s 内点击，在点击任务里同步克隆页面和样式表。
3. **首页悬停后马上点击，导航被入场动画拖住。** 悬停切换作品会重播标题／简介入场，预热任务要等这些动画结束（约 1.3s）才生成位图；点击会等待这个任务，导航被推迟约 0.7s。
4. **海报起飞前再复制一次目标页。** 目标海报落位后，同步复制新页面 DOM 作为模糊背景，并对整页再做一次采集和图片解码。
5. 首页每 6.5s 轮播一次，每次都重建整页快照。

## 改动

- **海报转场（首页→详情、媒体夹→详情、详情→媒体夹）不再复制 DOM。** 命中时只用预热的 240px 模糊位图。未命中时立即在实时页面上加 `backdrop-filter: blur(7px)` 镜片层；位图就绪后再淡入不透明遮罩并开始导航。没有 Worker/OffscreenCanvas 或位图失败时，才回退到原来的模糊 DOM 副本。
- **预热还在等入场动画时，点击直接中止它**，按当前画面采集；已进入采集阶段的任务照常等待。
- **目标页用同一镜片实时模糊。** 遮罩在 16%→48% 淡出，等价于原目标副本淡入；镜片在 70%→100% 淡出，等价于原遮罩淡出。不再复制目标页，也不再为目标页解码图片。
- **首页→媒体夹的飞出直接作用于实时的导航、轮播和舞台元素**，关键帧不变；遮罩在最后 42% 由透明变为 `#0b0d12`。动画在任务结束时取消。
- **返回首页仍需要清晰副本。** 预热副本改为原地提升为遮罩层，不再移动节点和恢复滚动。首页本身不再生成副本；其他页面在位图就绪后的空闲回调中生成。
- 背景采集按子树跳过 Emby 隐藏视图和动效层；移除已不使用的整页节点映射。

## 测量（仅夹具）

`tests/bench_home_motion.cjs`：Chromium 141 headless，软件合成，4 核 Linux 容器，1280×720。页面约 6000 个节点、约 600KB 样式表，模拟路由耗时 150ms。7 轮中位数，单位 ms。

- 同步：点击调用本身的同步耗时。
- 首帧：点击后第一帧主线程完成的时间。
- 海报动：`posterFirstMotionMs`。
- 导航：调用真实路由的时间。
- 起飞：`posterFlightStartsMs`。

| 场景 | 2.5.2 同步 / 首帧 / 海报动 / 导航 / 起飞 | 优化后 |
| --- | --- | --- |
| 首页→详情，命中 | 1.9 / 11 / 21 / 222 / 491 | 1.9 / 5 / 18 / 218 / 441 |
| 首页→详情，悬停后立即点击 | 7.4 / 19 / 34 / **935** / **1199** | 1.6 / 6 / 20 / **237** / **462** |
| 首页→详情，未命中 | 8.6 / 22 / 31 / 248 / 517 | 1.3 / 5 / 20 / 241 / 467 |
| 媒体夹→详情，命中 | **36.1 / 66** / 78 / 279 / 550 | **4.4 / 11** / 25 / 227 / 453 |
| 媒体夹→详情，未命中 | **37.3 / 92** / 109 / 326 / 590 | **3.0 / 21** / 40 / 246 / 475 |
| 详情→媒体夹，命中 | **22.7 / 42** / 50 / 253 / 620 | **3.1 / 11** / 21 / 222 / 512 |
| 详情→媒体夹，未命中 | **26.7 / 100** / 108 / 310 / 682 | **2.1 / 19** / 30 / 237 / 527 |
| 首页→媒体夹，命中／未命中 | 1.1 / 10 · 7.3 / 20 | 0.5 / 4 · 0.5 / 4 |
| 媒体夹→首页，命中 | 6.9 / 56 | 3.7 / 15 |
| 媒体夹→首页，未命中 | 43.6 / 90 | 39.9 / 87（仍需同步复制） |

海报转场期间超过 50ms 的长帧由 2–6 个降到 0–1 个。剩余的长帧主要出现在路由切换本身。媒体夹页面的位图约 210–310ms 就绪，返回首页用的副本约 300–370ms 就绪；2.5.2 两者都约 300–310ms。首页不再生成副本。

这些数字来自 4 核 Linux 容器里的 headless Chromium，不能直接和用户设备比较。2.5.2 原有的同步开销随页面 DOM 大小和设备速度增长；上一份验证记录中，大图冷绘制在 PC 约 269ms、Android 约 574ms。用户反馈的约 200ms 卡顿与此量级相符，但这只是推断，没有真机数据。

## 未验证范围

- 未在 Windows QtWebEngine、macOS 或 Android WebView 上运行，也没有接真实 Emby 服务器或真机。夹具支持 `--webengine` 和 `TIGEREST_ANDROID_FIXTURE`，需要在对应环境复测。
- `backdrop-filter` 的 GPU 开销没有测量。它取代的是原来带 `filter: blur(7px)` 的整页副本，量级相近，但 Android 和低端显卡需要实测。
- 位图仍不采集 CSS 渐变背景（原有限制）。冷点击时会从镜片的 7px 模糊过渡到位图的低分辨率模糊，与 2.5.2 未命中路径一致。

## 尚未处理

- 真实路由仍在遮罩 210ms 淡入后才开始。缩短淡入，或在按下时预取详情数据／海报图，可以让网络请求与淡入重叠；这会改变节奏，需要确认。
- 首页→媒体夹的放大入场仍同步复制新媒体夹页面（夹具中单帧约 85–125ms，在路由之后）。改为直接动画实时页面时顶栏不会一起缩放，需要确认视觉效果。
- 返回首页未命中缓存时仍同步复制当前页（约 40ms，首帧约 87ms）。
