## 最终行为

- 首页默认“继续观看”，不足 24 个作品时由当前媒体夹近期入库补齐。续看单集合并为父剧集，保留最近播放记录；设置可选最近入库、发行时间和评分。
- 首页作品进入真实详情，返回替换为对应媒体夹；媒体夹再返回首页。收藏使用原 Emby 收藏控制器，避免多压入首页历史。
- 触屏点击当前轮播作品或当前媒体夹直接进入；点击另一项先选择，之后点击进入。pointerdown 保存原选择，避免触屏的 focusin 提前改变选择而误跳转。轮播右上“查看更多”进入当前媒体夹。
- 首页底部竖版海报与实际详情海报衔接。手机原详情的竖图加入标题/资料左侧紧凑布局。返回通过真实虚拟列表定位作品；服务器合并版本造成 ID 不同时使用 PresentationUniqueKey 匹配。
- 媒体夹海报点击使用同一转场，包括没有经由首页打开的媒体夹。直接媒体夹的返回保留原历史归属；海报节点优先选真实 IMG，避免外层容器没有图片而降级。
- 页面交换前以连续淡入的模糊遮罩覆盖；高模糊图最多 240px 宽，仅生成一次，动画改变透明度和位置。最后 160ms 重新读取落点，适应 Emby 延迟响应布局。
- 当前页面在空闲时预热低分辨率位图及隔离 DOM 快照；点击消费现有快照。图片先异步缩小，后台线程合成。Android 非 origin-clean 应用内资源不能传入 worker 时，仅用已缩小的图在主线程合成，不修改跨域安全策略。
- 预热等待短入场动画结束，避免缓存隐藏/偏移的文字中间态。当前海报的鼠标聚焦不再重建同一背景；重复写入相同样式类不使缓存失效。
- PC 返回首页的退场副本原先透出静止原页面，造成两套轮廓；退场与入场层现在从第一帧使用实色遮底。首页进入媒体夹也修复同一问题。首页 enter/animateText 原关键帧与时序保留。
- 取消、注销、窗口改变、失败和减少动态效果时释放浮层、海报隐藏状态和输入锁。
- 修复点击时背景副本重新播放 `!important` 页面入场动画造成的 72px 纵向偏移；逐节点冻结动画/过渡，并保留移动详情布局样式。模糊背景不再额外缩放，低分辨率模糊通过扩展边缘像素保持原坐标且不漏出新页面。
- 海报第一帧使用实际点击位置，进入先小幅放大、退出先缩小，页面准备后从当前变换继续飞向目标。目标背景异步生成，不再拖住海报飞行或动画结束后的点击；后台晚到结果在结束/取消时释放。

## 性能与范围

原方案一次性源背景准备约 Windows 202–252ms、Android 230ms。细分冷启动测量：PC 绘制/缩小大图约 269ms，模糊约 10ms；Android 大图绘制可达 574ms，模糊约 32ms。主要耗时在大图缩放、裁切和合成，而非每帧模糊。

前一版的 `firstAnimationMs` 只量到遮罩动画创建，遗漏海报静止等待，不能代表点击后海报已开始移动。反馈复现中，PC/Android 海报真正开始飞行仍等待约 0.6–1.3s；原先只验证终点，也遗漏背景副本与真实页面的 72px 偏移。

修正版改用 `posterFirstMotionMs`：requestAnimationFrame 观察到海报矩形首次偏离源位置超过 0.15px 的时间。下面来自重新打包、重新加载的真实客户端，单位 ms；是 DOM 位置观测，不等同 GPU 首次呈现或高帧率录像：

| 路径 | Windows 窗口 | Windows 全屏 | Android 真机 |
| --- | --- | --- | --- |
| 首页→详情 | 129.3 | 18.9 | 24.3 |
| 详情→媒体夹 | 74.7 | 151.1 | 47.5 |
| 直接媒体夹→详情 | 45.2 | 128.6 | 36.9 |
| 直接详情返回媒体夹 | 69.1 | 79.9 | 49.1 |

上述十二次均命中缓存，海报落位误差均小于 0.008px。首次完整飞向目标仍需等待真实路由和布局约 0.5–0.8s，但等待期间海报已经从源位置开始连续变换。PC 样式/快照接入和合成仍有成本，不能声称零延迟。另在窗口、全屏和手机的十二条路径记录实际目标海报与背景副本矩形，差值均为 0px；检查了真实客户端动画中途画面。350ms 慢解码夹具同时检查源矩形首帧吻合、80ms 内海报本身已移动；2s 目标解码夹具检查 1.4s 时输入锁和海报隐藏已释放、晚到结果不新增浮层。

缓存只保留当前页面的一张低分辨率位图和一个隔离快照，不是整站缓存。位图为 Windows 240×128/135、Android 240×268，原始 RGBA 大小约 120–251KiB；不包含 DOM、浏览器原图及 GPU 内存。内容、滚动、viewport、路由和身份重置使其失效；取消释放快照/位图，并发解码失败也等待迟到位图后统一关闭。

动画期间 requestAnimationFrame 间隔中位数 Windows 16.7ms、Android 8.3ms；P95 有 16.7–50ms 波动。这些包含路由等待和快照准备，仅为回调间隔，不能当作实际 GPU 帧率或显存占用。缓存未就绪、页面仍在加载或设备负载高时的点击耗时不能由命中测量保证。
