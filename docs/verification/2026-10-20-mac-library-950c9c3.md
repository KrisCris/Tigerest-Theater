# Jellyfin 2.9.0 Mac 媒体库入场增量（950c9c3）接收说明

- **前置：** `83c19e2bb6e4abc2bef0b7bb8fb056162a0deb08`（上一包《Jellyfin-2.9.0-Mac媒体库入场增量-07722dc》的 source）。
- **接收方式：** 包内 git bundle 自 83c19e2 起，到包内 `manifest.json` 的 `source` 为止。先运行 `git bundle verify`，再 fetch 后快进或 cherry-pick。
- **不覆盖 Apple 代码：** 本包只改共享文件 `native/homeTransitions.js` 和测试/文档，没有 Apple 独立产品文件，也不要用它覆盖 Mac 自有的 Apple 修改。

## 共享改动

1. `4680916` 入场副本先在不透明遮罩下预绘制。
   - 媒体库入场动画开始前，先在遮罩下以最终尺寸、0.01 不透明度画 3 帧，并带 `will-change: transform, opacity` 保持同一图层。然后照常播放原来的 460 ms 入场动画。
   - 原因：手机上整页副本的首次栅格化和图片解码，曾占用入场开头 33–133 ms 的帧。
   - 预绘制期间副本不透明度始终 ≤0.01，不会闪现。
2. `950c9c3` 等可见卡片封面就绪后再复制。
   - 判断标准：目标页视口内没有带 `data-src` 的元素，即 Jellyfin 懒加载已经设好封面。仍受原来 2.4 s 上限约束。
   - 原因：冷启动时，旧逻辑复制的那一刻 12 张可见卡片都还没有封面（`data-src` + `lazy-hidden`）。副本带着空白卡片飞入，遮罩撤掉后封面才突然出现。
   - 已在真实 Jellyfin 10.11 远程站点用 Qt 诊断确认这一现象。
