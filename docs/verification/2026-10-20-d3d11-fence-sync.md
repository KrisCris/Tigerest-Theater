# Windows 花屏：共享纹理双向 fence 同步与首页轮播交叉淡化

2026-10-20 07:00–13:20 JST。起因：用户录屏中首页轮播空闲时出现花屏（整页只剩背景、卡片块状缺失）和暗闪，窗口被其他窗口遮挡时更容易出现。以下均为本机实测（Windows 11 23H2、RTX 4090、驱动 32.0.16.1664、2560×1440 240 Hz）；Mac/Android 未涉及本补丁。

## 根因

- 已有的 `qtwebengine-6.9.3-d3d11-producer-sync.patch` 只保证“Chromium 写完再交给 Qt 读”。
- 缓冲区轮换时，Qt 在 `swapFrame` 把旧前缓冲交还 Chromium，此时 Qt 的 GPU 可能仍在采样它，Chromium 已经开始画下一帧。Qt 于是显示画到一半的帧（读后写冲突）。
- 生产者等待日志全程正常（`completed=1`），说明不是原补丁失效，而是缺另一个方向的同步。

## 修复

- `qtwebengine-6.9.3-d3d11-fence-sync.patch`：在 ANGLE 设备和 Qt 设备之间共享两个 `ID3D11Fence`，两个方向都改为 GPU 队列等待，CPU 不阻塞。原理见 `dev/windows/qtwebengine/README.md`。
  - fence 不可用时自动回退到原 CPU 生产者等待。
  - `TIGEREST_D3D11_FENCE_SYNC=0` 用于关闭对照。
- `native/homeGallery.js` 轮播交叉淡化：
  - 新海报和背景图加载并淡入期间，上一部作品的图层留在下面。
  - 新图 450 ms 内未加载时，旧图才淡出，因此仍满足“停滞的图片不能把旧作品留在新标题后面”。
- 构建与测试工具：
  - `build.ps1` 记录已应用的整组补丁（`.tigerest-patches`），叠加补丁的构建目录可以重跑。
  - `Enter-TestEnvironment.ps1` 改用该构建的 `CMAKE_INSTALL_PREFIX` 作为暂存运行库目录。原来固定用 `build\output`，在本机那是另一个装着旧 DLL 的实例，CTest 的启动测试因此加载了旧 WebEngine。

## QtWebEngine 构建

- 源码：官方 6.9.3 归档（SHA256 与 README 一致），按 `patches.txt` 应用 4 个补丁。
- 产物：核心 DLL SHA256 `19587da24132f988f297ed2310b4a591d6d5e9d21a96bcb28f959cb7145fb8dc`，清单列出 4 个补丁及其 SHA256。
- 中文 Windows 上有两个构建坑：ATL 路径、链接器 GBK 输出。处理方法写入 README，均未改 VS 安装。

## 花屏对照（WGC 单窗口抓帧）

条件完全相同：

- 隔离测试配置，登录真实远程服务器，首页轮播空闲。
- 遮挡窗口每 2 s 盖住、2 s 移开。
- 每组 360 s。

指标：

- 以 32 px 块为单位，标记“与前后帧都差异大、而前后帧彼此相近”的单帧尖峰。
- ≥100 块即整页级缺失。

| 运行库 | 抓帧 | ≥100 块 | 20–99 块 | 2–19 块 |
|---|---|---|---|---|
| 新 DLL，fence 开（默认） | 68,760 | **0** | 1 | 21 |
| 新 DLL，`TIGEREST_D3D11_FENCE_SYNC=0` | 62,760 | 26 | 9 | 42 |
| 旧 DLL（仅生产者等待） | 67,558 | 11 | 3 | 22 |

人工复核：

- fence 关的最大标记帧是真花屏：上下半区为块状的半绘制页面，前后帧正常。
- fence 开的 2–19 块小标记抽查为封面行滚动的正常运动。

较早一次旧 DLL 基线：600 s 内 186 帧，其中 ≥100 块 126 帧。那次是自然遮挡，条件不同，不与上表直接比较。

## 测试

- CTest 全套 108 项，暂存包 `output-fence` 使用新运行库：**108/108 通过**。
  - 第一次运行 107/108。`test_webengine_startup` 失败，原因是测试环境把另一实例的旧 DLL 放在 PATH 前面，修正 `Enter-TestEnvironment.ps1` 后整套重跑通过。
  - `test_window_chrome` 是否按 TESTING.md 跳过无边框最大化用例，本次 CTest 日志里看不到。
- `test_webengine_startup` 现检查两条路径：
  - 默认路径的 `producer fence ready` 与 `consumer fence ready`，且没有 `fence sync disabled`；
  - `TIGEREST_D3D11_FENCE_SYNC=0` 时的 `producer wait: completed=1`。
  - 直接对 `output-fence` 单独连跑两次均通过。
  - 另有一次在窗口未渲染时失败（Qt 未调用 `texture()`），等待时间已从 6 s 放宽到 15 s。
- 首页 UI 夹具 8 项在空闲机器上全部通过：gallery、entrance、touch、backdrop cache、jellyfin home layout、motion、motion cache、heading fit。
  - 编译占满 CPU 时，其中 3 项曾超时。
- 新增的轮播检查“切换后旧图仍在、无暗隙”：
  - 对打包了旧 `homeGallery.js` 的 `output-regression20` 失败；
  - 对新包通过。

## 120 帧呈现

测量方法：Desktop Duplication 统计转场期间真正呈现的帧，窗口最大化 2560×1356 CSS px，dpr 1.5，3 轮。

| 运行库 | 10 段转场平均呈现帧率 | 详情页／返回各段 |
|---|---|---|
| 新 DLL（fence） | 135.5 fps | 151／155、134／167、140 |
| 旧 DLL | 130.7 fps | 137／174、144／126、133 |

- 差异在逐轮波动范围内，未见 fence 带来的开销。
- 两者 rAF 均约 240 fps。

## 未验证

- 只在本机一种 GPU 和驱动上验证。不支持 `ID3D11Device5` 或共享 fence 的设备会走回退路径，回退路径的效果等同旧 DLL。
- 抓帧检测是单帧尖峰统计，不覆盖所有像素和所有帧。
