# Windows 弹幕首搜与一周日期容差（2026-10-08）

## 复现证据

已安装 Windows 客户端日志中，12:55:05 的自动搜索与 12:55:13 的手动搜索使用相同关键词，均返回作品 19635。自动搜索提示未找到剧集；手动搜索随后请求 `/api/v2/comment/196350003`，解析到 2421 条评论。没有修改用户播放器、认证信息或历史设置。

对应 Emby 单集为 S1E3，首播日期 `2026-07-20`；生产弹幕接口的同一 E3 为 `2026-07-17`。只读查询核对了该集的编号、标题与日期。旧自动匹配要求日期完全相同，拒绝了相差 3 天的正确候选；手动搜索列出候选时没有这项限制。

## 修复规则

- 仍优先采用既有精确日期匹配，包括用单集标题或集号消除同日批量播出歧义、映射跨季连续编号。
- 只有精确匹配未成功、播出日期相差不超过 7 个日历日（包含第 7 天）、集数一致、单集标题相似度至少 0.85，并且所有搜索结果检查后只有一个候选，才采用日期容差。
- 缺少真实单集标题（空标题或「第 8 集」等占位名称）时，经用户确认允许按作品、集数和日期匹配：作品相似度至少 0.85、集数一致、日期相差不超过 7 天且全局候选唯一才加载。相似度 0.75 至 0.85 的其他作品若也存在同集数附近日期，视为无法确认唯一性。
- 日期无效、超过一周、集数不符、有真实标题但不匹配、多个候选，以及精确日期仍有歧义时，保留手动匹配提示。
- 搜索或剧集详情失败、无效或超时，表示无法确认唯一性；不能采用附近日期候选。详情请求使用 15 秒期限；换片后其定时器与迟到响应不能影响下一部影片。
- 候选按服务地址、作品 ID、剧集 ID 区分；同一来源的重复记录去重。仓库支持的 [danmu_api 按部署分配自增 ID](https://raw.githubusercontent.com/huangxd-/danmu_api/main/danmu_api/configs/globals.js)，因此不同服务同时返回附近日期候选时仍需手动选择，不推定它们是镜像。
- 日期采用公历日数计算，避免时区、夏令时及 Windows `os.time` 对 1970 年前日期的限制。
