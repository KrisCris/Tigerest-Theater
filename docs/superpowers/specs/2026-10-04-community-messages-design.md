# 消息中心与网页消息后台

用户要求在 V2.3.3 上增加个人发言与相关回复汇总，以及能查看全部消息的网页后台。沿用现有评论系统，不引入私信或独立注册。

## 用户界面

顶栏消息入口与未读回复计数，仅大河受信任 Emby 登录用户可见。独立弹窗包含“收到的回复”“我的发言”，分页、刷新、空状态、单条已读和全部已读。我的发言包括主评论与回复；收到的回复包括他人对自己评论/回复的直接回复，不向自己发送通知。消息包含作品/单集标题、作者、时间、原发言和纯文本正文。查看讨论打开可访问的 Emby 详情，选择原话题并定位评论；账号切换、退出立即取消请求与清空数据。删除的正文只显示占位。

## 网页后台

独立静态网页，使用现有 Emby 用户名和密码登录，凭证只留在内存。身份由 `/me.isCommentAdmin` 判断；全站读取由服务端再次授权。后台分页展示全部评论与回复，按关键词、类型与删除状态筛选，可以展开同一讨论。现有删除/禁言/审计接口保持兼容；本次网页以消息查看为主。响应乱序、筛选改变和退出不能重现旧数据。所有正文、标题、作者名按纯文本显示。

## 服务契约与部署

复用 HTTP18443 `/community/v1` 认证、限流与错误封装。新增接口的字段与授权语义记录到 `docs/community-messages-api.md`。个人查询在服务器按令牌所有者和当前媒体权限过滤；历史发言也可查询，回复通知/已读状态由服务端持久化。全站查询只允许服务端配置的评论管理员。全部已读使用服务器快照水位，不能误读操作期间新到的回复。

现有后端位于独立私有仓库；获得路径后在该项目实现数据库查询/通知与部署。未获得后端代码时，本仓库能完成客户端、网页、打包和契约测试，但不能把模拟数据验收声称为生产已接通。网页包由 `tools/build_community_admin.py` 将公共请求层复制到独立目录，部署在评论服务同源 `/community/admin/`，无需新的框架依赖。

## 验收

Node 请求测试验证会话级读取、Item 权限保护、游标/筛选参数、已读水位与取消。Chromium/QtWebEngine 测试真实 UI 的列表、纯文本、分页、未读、定位、筛选竞态、普通用户拒绝访问与退出清理。重新构建客户端验证嵌入脚本资源；网页构建检查独立包可以加载。生产接口验证必须有真实后端，不能以本地 fixture 替代。

## 2026-10-05 正式对接与 2.4 范围修订

本节取代上文尚未确定的服务路径与后台部署设想。用户提供的 `Y:/community-api.md` 为正式契约，已同步到 `docs/community-api.md`。个人列表使用 `/me/comments`、`/me/replies`，已读使用 POST `/me/replies` 的 messageIds 或不透明 readThroughToken。定位使用原评论列表的 anchorId，不使用草稿中的 /messages、/context 路径。

后台已在独立私有服务的局域网 18444 部署；本次客户端不重复实现或发布该后台。仓库原有未跟踪 web 草稿保留，不加入客户端发行包。客户端原有评论管理工具继续保留。

503 保留最近成功列表和未读计数；账号切换立即清空。轮询不能覆盖用户正在查看的快照，也不能回滚较新的已读操作。过期快照刷新后由用户再次点击全部已读。availability=unavailable 使用通用占位，canNavigate=false 可打开媒体但不锚定评论。

高刷新率：保留 Windows RIFE 生命周期内的音频时钟策略；为 Windows 超过 120 Hz 的普通播放和外部补帧提供默认开启且可关闭的兼容选项，将显示同步改为音频时钟。120 Hz 及以下保留原同步设置。显示器切换时重新选择，不改变物理刷新率、补帧倍率或性能保护。系统 mpv.conf 与高级手动覆盖仍优先。音频时钟的显示周期统计可能不可用，不作为 jitter=0 宣传；允许分数帧率产生正常重复/丢帧。
