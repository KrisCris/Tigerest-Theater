# 大河影院 mpv.conf 编辑器与自定义配置设计

日期：2026-10-23（Asia/Shanghai）

代码基线：`claude/apple-2.9.4` 的 `5e35995`；开发分支 `claude/apple-2.9.4-next`，计划在 2.9.4 PC 端完成后合并。

状态：方案已在对话中与用户逐项确认，本文是设计，不是实现或验收报告。适用 Windows 与 macOS 桌面客户端（Qt）；iPad/iPhone 不在本期范围。

## 1. 目标

1. 软件始终只读取一份 `mpv.conf`，即用户在设置页编辑的那一份；不再有多个来源互相覆盖。
2. 用户可以自定义画质参数、着色器、`vf` 滤镜和自定义档位，但不能破坏现有功能链路（uosc、弹幕、RIFE、SVP、统计页、宿主窗口）。
3. 软件注入或由其他设置决定的配置，全部以只读形式写在这份文件里，并附中文说明，使用户和用户侧的 AI 能看到完整链路。
4. 写坏时可以一键恢复默认配置；配置加载失败时客户端不能崩溃。

## 2. 现状（2.9.3 及之前）

| 机制 | 现状 | 问题 |
| --- | --- | --- |
| 配置模式 | 内置 / 自动 / 系统三种（`MpvConfigManager::initialize`） | 多个来源，系统模式下大量设置失效 |
| 内置 `mpv.conf` | 每次启动由 `resources/mpv/mpv.conf.in` 重新生成，填入档位、SVP 接口、脚本列表三处占位 | 用户直接改会被覆盖 |
| `user-overrides.conf` | 内置配置末尾 `include` | 着色器会被切档时的 `change-list glsl-shaders clr` 清掉 |
| 高级页 `other_conf` | 每次播放逐条 `setProperty` | 写 `vf=` 会替换整条链，冲掉 `@tigerest-rife` |
| 画质参数覆盖 | 仅在打开「用下方高级参数覆盖当前档位」时由 `setMpvPreset()` 一次性写入 | 开关一开，未改动的项也会覆盖所选档位；播放中切档后覆盖丢失 |
| 其他设置页 | 视频、音频、字幕页在每次播放时直接写 mpv 属性（`setVideoConfiguration` 等） | 盖掉配置文件中的同名项 |
| 播放中切档 | uosc 菜单（`profile_menu.lua`）与快捷键（`MpvVideoItem.cpp`）只切 mpv 档位 | 不写回设置页的画质预设 |
| `uosc.conf` | 每次启动由资源覆盖 | 维持现状，本期不开放 |
| 资源部署 | `copyResourceTree` 只覆盖、不删除 | 被淘汰的内置着色器永久残留 |
| 初始化失败 | `mpvcontroller.cpp` 中 `mpv_initialize` 失败直接 `qFatal` | 用户配置写坏会导致客户端无法启动 |

## 3. 已确定的决策

| 主题 | 决定 |
| --- | --- |
| 配置模式 | 删除。只读取软件目录中的用户 `mpv.conf` |
| 文件 | 软件目录中只有两份：只读的 `mpv.default.conf`（随版本更新）与用户的 `mpv.conf` |
| 恢复默认 | 把 `mpv.default.conf` 重新写入 `mpv.conf` |
| `uosc.conf` | 不开放编辑，只能通过设置项调整 |
| 设置页 | 「MPV 画质与插件」与「高级」合并为一页：上方是设置项，下方是 `mpv.conf` 编辑器，两边实时同步 |
| 画质档切换 | 切档即整组参数切换；播放中切档后，设置页画质预设同步切换 |
| 只读内容 | 软件注入与其他设置页决定的配置写在文件中，灰色、不可改、附中文注释 |
| 冲突项 | 与已开启功能冲突的用户行自动注释并标记，功能关闭后恢复 |
| AI 约束 | 只允许导出文本给 AI，再粘贴回编辑器；不允许直接改源文件。软件每次启动仍做校验兜底 |
| 2.9.4 迁移 | 直接覆盖为新默认配置，设置页显示一次说明；旧自定义内容存入备份文件 |
| 滤镜库 | 内置与用户目录分开；按清单更新内置文件，不动用户文件 |
| 重复着色器 | `resources/mpv/shaders/` 根目录下 52 个与 `Anime4K/` 完全相同且无引用的文件已在本分支删除 |

## 4. 用户 `mpv.conf` 的结构

文件分三块，顺序固定。mpv 按顺序解析，后写的同名项生效，所以软件管理的尾部能保证锁定项最终生效。

```text
# ==== 大河影院管理区·头部（只读）====
# 配置版本：2.9.4；默认配置校验值：<sha256>
# 修改须知：见设置页「复制给 AI」或 <AI 说明文件路径>
# ==== 头部结束 ====

# ---- 用户区：全局选项 ----
...
# ---- 用户区：画质档位 ----
[tigerest-default]
...
[tigerest-liveaction]
...
[tigerest-aggressive-test]
...
# 用户自建档位（可选）
[tigerest-user-xxx]
...

[default]
# ==== 大河影院管理区·尾部（只读，每次启动由软件重写）====
# 每一项上方一行写明：由谁决定、在哪里修改
...
# ==== 尾部结束 ====
```

- 管理区以标记行界定。软件每次启动、每次相关设置变化时只重写管理区，用户区原样保留。
- 管理区开头必须回到 `[default]`，否则会落入最后一个档位段。现行模板已用这一写法。
- 说明注释写在配置行的上一行，与现行模板风格一致，不在值后面追加注释。
- 播放过程中软件临时执行、不在配置文件里的动作，以注释形式写在尾部，例如：
  - 开启 RIFE 时，播放中追加 `@tigerest-rife` 滤镜，停止时移除；
  - 切换画质档时先清空着色器，再套用所选档位；
  - 开启弹幕时，弹幕脚本可能把 `video-sync` 临时改为 `display-vdrop`（`uosc_danmaku/modules/render.lua`）。

## 5. 配置项归属

所有规则来自同一份配置项目录（见第 11 节），编辑器、校验、AI 说明都从它生成。

### 5.1 永久锁定（软件决定）

不得出现在用户区，包括各个档位段内：

`vo`、`wid`、`gpu-context`、`gpu-api`、`config`、`config-dir`、`include`、`input-conf`、`input-default-bindings`、`input-ipc-server`、`load-scripts`、`script`、`scripts`、`script-opts`、`osc`、`load-stats-overlay`、`idle`、`keep-open`、`force-window`、`save-position-on-quit`、`reset-on-next-file`、`log-file`，以及全局的启动档位行 `profile=`（由画质预设下拉框决定）。

档位段内的 `profile=` 用于继承，允许使用。

### 5.2 由其他设置页决定（只读显示）

这些项改为由设置页写进尾部管理区，同时在当前播放中立即生效，不再每次播放单独写属性：

| 设置页 | 配置项 |
| --- | --- |
| 视频 | `video-sync`、`hwdec`、`hwdec-image-format`、`deinterlace`、`demuxer-max-bytes`、`display-fps-override`（自动检测） |
| 字幕 | `sub-font`、`sub-scale`、`sub-pos`、`sub-align-x`、`sub-color`、`sub-border-color`、`sub-border-size`、`sub-back-color`、`sub-ass-override`、`sub-ass-style-overrides` |
| 音频 | `audio-device`、`audio-channels`、`audio-exclusive`、`audio-spdif`、`audio-normalize-downmix`、`audio-swresample-o` |
| 弹幕 | `script-opt=uosc_danmaku-*` 样式项 |

现行模板里的 `sub-font`、`sub-scale`、`sub-border-size` 等默认值随之移入尾部管理区。

### 5.3 本页设置项（编辑用户区）

MPV 页上方保留的设置项直接编辑用户区对应行：画质参数（缩放、去色带、HDR、抖动等）、`alang`、`slang`、`cache-pause`、`demuxer-max-back-bytes`、`screenshot-format`、`screenshot-directory`。

- 画质参数编辑「当前所选画质档」的那一段；选「真人」就改 `[tigerest-liveaction]` 中的行。
- 同一段内同一项出现多次时，以最后一行为准，表单也编辑这一行，并提示存在重复。
- 用户写了下拉框中没有的值，表单显示「自定义：<值>」。
- 某项在段内不存在时，表单显示继承来的值，修改时在该段末尾插入新行。

### 5.4 条件锁定

功能开启时，与之冲突的用户行改为带标记的注释；功能全部关闭后恢复：

```text
#[暂停执行:RIFE] vf-append=@user-1:fps=60
```

- 只恢复带此标记的行，不影响用户自己写的注释。
- 一行可同时被多个功能暂停，标记列出全部原因，例如 `#[暂停执行:RIFE,弹幕]`；所有原因解除后才恢复。
- 只跟随设置开关变化，不跟随运行时状态。RIFE 因跟不上或冲突在播放中自行停用时，不改文件。
- 开启功能时，除改文件外还要在当前播放中撤销这些项（例如移除对应标签的滤镜），否则当前这一集仍会冲突。
- 切换时弹提示：「RIFE 已开启，你写的 N 行配置已暂停执行」；关闭时：「已恢复执行 N 行配置」。

条件锁定清单：

| 功能 | 被暂停的用户配置 |
| --- | --- |
| RIFE | `vf` 中改变帧率或插帧的滤镜：`fps`、`framerate`、`minterpolate`、`vapoursynth`，以及名称或参数中含 `svp`、`rife` 的项。这与 `FrameInterpolationController::conflict()` 的判定一致 |

`interpolation`、`tscale` 与 RIFE 同时开启是否冲突，见第 13 节。

## 6. 设置页

### 6.1 页面结构

- 「高级」页删除，`other_conf` 并入编辑器。
- 删除的设置项：`configMode`、`systemConfigDir`、`advancedProfileOverrides`、`other_conf`，以及迁移标记 `configModeMigrated`、`embeddedConfigDefaultMigrated`。
- 上方保留：渲染后端（需重启）、画质预设、uosc、弹幕、控制台开关，以及第 5.3 节的设置项。
- 页面顶部固定说明：「2.9.4 起 mpv 配置方式已更新，旧版自定义配置不再生效，请在下方编辑器中重新设置。旧内容已备份到：<路径>」。
- 说明附近给出滤镜库路径 `<配置目录>/shaders/user/`，并提供「在 Finder/资源管理器中打开」按钮。

### 6.2 画质预设双向同步

- 设置页选择预设：写用户 `mpv.conf` 的启动档位（管理区），并在播放中立即切档。
- 播放中通过 uosc 菜单或快捷键切档：写回 `shaderPreset` 设置，设置页同步显示。
- `profile_menu.lua` 中写死的每档着色器数量改为根据当前文件实时计算，否则用户改了档位里的着色器，切档时会误报「切换失败」。
- 用户自建的 `[tigerest-user-*]` 档位出现在 uosc「滤镜」菜单和设置页下拉框中，以 `profile-desc` 作为显示名。

### 6.3 编辑器

- 显示整份文件。管理区为灰色只读；被条件锁定暂停的行标黄并显示原因。
- 左侧行号栏在每两行之间提供「＋」。点击后打开选择面板：
  - 面板顶部显示插入位置所属的段，例如「将添加到：真人档」或「全局」；
  - 类别：画质参数、着色器（从滤镜清单选择）、字幕、`vf` 滤镜、新建自定义档位；
  - 锁定项照常列出但不可选，并显示原因，例如「由字幕页设置」「RIFE 已开启，暂不可添加」；
  - 同段已存在的项不重复插入，改为跳到该行；
  - 确认后插入「中文说明注释 + 配置行」。
- 点击已有行，可用同一面板修改。
- 管理区内不显示「＋」。
- 表单与文本实时双向同步；解析器必须原样保留用户的注释、空行和顺序。
- 输入时逐行检查，错误行标红并在行尾提示原因（规则见第 7 节）。
- 离开页面时若存在错误，弹窗：「强行使用」或「返回修改」。
- 「恢复默认配置」：确认后用 `mpv.default.conf` 覆盖，覆盖前把当前内容存入备份。
- 「复制给 AI」：一次复制 AI 说明与当前完整文件。
- 粘贴整份文本时：只采纳用户区的内容；粘贴内容改动了管理区时丢弃这些改动，并提示「已忽略 N 行对锁定内容的修改」；应用前先显示改动的行，让用户确认。

## 7. 校验

| 层级 | 内容 | 时机 |
| --- | --- | --- |
| 写法 | `key=value` 格式、段标题、引号配对、空值 | 编辑时 |
| 配置项 | 名称是否存在、类型、取值范围、可选值；数据来自运行中 mpv 的 `options` 与 `option-info/<名称>`，缓存后供编辑器离线使用 | 编辑时 |
| 归属 | 用户区出现永久锁定或其他页面管理的项 | 编辑时、每次启动 |
| 引用 | 着色器文件是否存在；`profile=` 引用的档位是否存在 | 编辑时、每次启动 |
| `vf` | 标签重名；与 RIFE 冲突的关键词；`hwdec` 为纯硬解时使用 CPU 滤镜给出警告；改帧率的滤镜给出警告 | 编辑时 |
| 重复 | 同一段内同一项写了多次 | 编辑时（警告） |
| 应用 | 滤镜名或滤镜参数错误；mpv 报出的配置错误 | 应用或播放时，从 mpv 日志捕获并回显到编辑器 |

## 8. 加载与失败兜底

1. 启动时：读取用户 `mpv.conf`，重写头部与尾部管理区，校验用户区。
2. 用户区出现锁定项（例如被外部工具直接改过文件）：在内存中跳过这些行再加载，编辑器标红，并在设置页提示。
3. `mpv_initialize` 失败：不再 `qFatal`，改用 `mpv.default.conf` 重新创建并初始化 mpv，然后弹窗：「你的 mpv 配置没能加载，本次已使用默认配置，请到设置页检查」。
4. 编辑中选择「强行使用」的错误行由 mpv 自行处理；结果依赖第 13 节中待确认的 mpv 行为，最终都由第 3 步兜底。

## 9. 升级

- 头部记录配置版本和生成时默认配置的校验值。
- 升级后：
  - 用户区与旧默认配置一致（用户未改过）：静默替换为新默认配置；
  - 用户改过：保留不动，执行一次校验；有问题时标红，并提供「查看新版默认配置差异」，不自动合并。
- 会导致用户配置失效的典型情况：着色器改名或移动；我们改了档位名；mpv 删除或改名配置项（例如 0.37 删除 `tone-mapping-mode`）。

### 9.1 2.9.4 一次性迁移

据用户确认，目前没有用户在使用系统或自动模式，因此不做导入。

1. 把 `user-overrides.conf` 的内容、`other_conf` 的内容、旧画质参数覆盖值原样写入 `旧版自定义配置备份.txt`。
2. 用新默认配置生成用户 `mpv.conf`。
3. 删除第 6.1 节列出的设置项。
4. 设置页显示第 6.1 节的说明。

## 10. 滤镜库

### 10.1 目录与更新

- 内置着色器：`<配置目录>/shaders/<组>/...`；用户着色器：`<配置目录>/shaders/user/`。用户目录与内置目录分开，避免以后内置同名文件覆盖用户文件。
- `<配置目录>` 当前位于各用户档案的数据目录下（`ProfileManager::activeProfile().dataDir("mpv")`），因此用户滤镜也按档案分开。
- 构建时生成内置清单 `shaders/manifest.json`，记录相对路径和 sha256。
- 更新时只新增、替换、删除清单中的内置文件；`user/` 目录完全不动。
- 用户直接修改的内置文件仍会在更新时被覆盖；说明中写明「修改内置滤镜请先复制到 `user/`」。
- 有了清单后，被淘汰的内置文件也会在更新时清理，不再残留。
- 需要大规模替换内置滤镜的版本，在更新说明中提前写明：「本次更新会替换旧的内置滤镜库，如有自定义滤镜链路，请在播放前检查是否用到了旧滤镜」。

### 10.2 空滤镜检测

- 每次启动检查用户 `mpv.conf` 中引用的着色器文件是否存在。
- 升级后首次启动发现空滤镜：弹窗提示，并引导到设置页对应行。
- 平时发现空滤镜：只在编辑器中标红。

### 10.3 滤镜清单

内置 87 个着色器（去重后），分 6 组。每个文件在数据目录中记录：

| 字段 | 说明 |
| --- | --- |
| 作用 | 色度重建、放大、缩小、修复、降噪、线条处理、暗部或高光处理 |
| 适合片源 | 动画、真人、通用 |
| 触发条件 | 例如放大类只在输出大于片源时运行；SSimDownscaler 只在缩小时运行；KrigBilateral 只对 4:2:0 色度起作用 |
| 性能开销 | 低、中、高、极高（相对档位） |
| 效果强度 | 轻、中、强，加一句观感说明 |
| 搭配与冲突 | 例如两个作用于亮度放大的滤镜不应叠加；Anime4K 的固定顺序 |

各组概况：

| 组 | 文件数 | 主要用途 |
| --- | --- | --- |
| Anime4K | 52 | 动画修复（Restore CNN/GAN）、放大（Upscale CNN/GAN/DoG）、降噪、线条收细（Thin）、暗线加深（Darken）、高光钳制、预缩小 |
| ArtCNN | 17 | 动画向卷积放大；C4F8/F16/F32 为规模，DS、DN 为带锐化或降噪的变体，含旧版与 v0 |
| CfL | 6 | 色度重建（KrigBilateral、CfL Prediction、JointBilateral、FastBilateral、kACfL） |
| FSRCNNX | 8 | 通用或动画向卷积放大，含 LineArt 与 distort 变体 |
| RAISR | 2 | RAVU 放大（lite 与 zoom） |
| SSim | 2 | 高质量缩小（Downscaler）与放大后锐化（SuperRes） |

性能档位先按模型规模给出相对顺序（S < M < L < VL < UL < UUL；F8 < F16 < F32）。实测由 `tools/measure_mpv_shaders.py` 完成：mpv gpu-next 渲染 1920×1080 窗口，放大类用 1066×600 的 4:2:0 测试图（约 1.8 倍），缩小类用 3840×2160；等每个处理步骤都有 120 帧计时后，取最近 48 帧 `vo-passes` 计时的中位数求和，再减去不加着色器时的耗时。结果写在 `resources/mpvconf/shader-timings.json`，由 `tools/generate_mpv_shader_catalog.py` 合并进清单。目前只在 Apple M4 Pro 上测过；Windows 独显机的数据待 PC 端补测。1 ms 以下的差异受显卡自动降频影响，不能用来排序。

## 11. 统一数据源

新增 `resources/mpv/catalog/`：

- `options.json`：配置项名称、中文说明、类型与取值、归属（永久锁定、哪个设置页、条件锁定原因）、面板类别、注释模板；
- `shaders.json`：第 10.3 节的滤镜清单。

由它生成或驱动：编辑器的「＋」面板与表单、校验规则、管理区注释、AI 说明 `.md`、设置页里的滤镜清单。新增配置项或更换滤镜时只改这里。

## 12. 给 AI 的说明（生成内容大纲）

`复制给 AI` 导出的 `.md` 包含：

1. 使用方式：只能把修改后的完整文本交还给用户，由用户粘贴回设置页编辑器；不得直接修改 `mpv.conf` 源文件。
2. 文件结构：头部、用户区、尾部的标记行；管理区内容不得改动。
3. 永久锁定项、其他设置页管理的项、条件锁定项及当前状态。
4. 当前可用的着色器清单和路径写法：内置写 `~~/shaders/<组>/<文件>`，用户写 `~~/shaders/user/<文件>`。
5. 档位规则：内置三档名称；自定义档位以 `tigerest-user-` 开头并写 `profile-desc`。
6. `vf` 规则：必须带 `@user-` 标签；禁止的滤镜；顺序；对 `hwdec` 的要求。
7. 注释规范：每个配置行上一行写中文说明。
8. 自检清单与恢复方法。

## 13. 待确认问题（实现时的结论）

1. RIFE 与 `interpolation`：RIFE 输出的已是补好帧的画面，mpv 的 `interpolation=yes` 会在其上再做一次帧混合，原模板也正是为避免与外部插帧重复而写死 `interpolation=no`。因此把 `interpolation=yes` 加入了 RIFE 条件锁定；`tscale` 只在 `interpolation` 开启时起作用，不单独锁定。这是按原理判断，没有做画面对比实测。
2. 错误行：用 libmpv 0.41 实测，未知配置项、非法取值、写坏的行、引用不存在的档位或 `include` 文件都只记录警告并跳过，`mpv_initialize` 仍然成功。所以「强行使用」的提示写的是「mpv 会跳过它无法识别的行」。初始化失败后回退到默认配置的兜底仍然实现了，用于其他原因的失败。
3. 「＋」面板的「自定义档位」页可以以任一现有档位为基础新建档位（写 `profile=` 继承），满足「复制当前档位」的需要。

## 15. 测试与验收

- 解析器：任意文本解析后再输出须逐字节一致（保留注释、空行、顺序）；表单修改只改动目标行。
- 管理区：重写只影响标记之间的内容；用户区中的锁定项被跳过并报告。
- 条件锁定：开关 RIFE 时标记行正确注释与恢复；多原因叠加；运行时自停不改文件。
- 迁移：备份文件内容完整；旧设置项被删除。
- 滤镜库：按清单更新；`user/` 不受影响；淘汰文件被清理；空滤镜检测。
- 兜底：故意写坏的配置导致初始化失败时，自动回退到默认配置且客户端不崩溃。
- `tests/test_bundle_integrity.py` 中关于内置配置的检查同步改为检查 `mpv.default.conf`。
- 报告中区分受控测试（固定样本、隔离配置档）与真实播放验证。Windows 测试按 `dev/windows/TESTING.md` 准备环境；macOS WebEngine 测试需屏蔽「移动到应用程序」提示。

## 16. 实现记录（与上文不同或补充的地方）

- **其他设置页的值**：视频、字幕、音频页的值写进尾部管理区，同时仍在每次播放时直接设置到 mpv，两处的值来自同一份计算（`MpvConfigManager::videoOptions()` 等）。用户区不能写这些项，所以不会互相覆盖。
- **弹幕外观**仍写在 `script-opts/uosc_danmaku.conf`（软件管理，不开放），没有并入 mpv.conf；尾部管理区里有说明。
- **切档由软件执行**：设置页、uosc 菜单（`profile_menu.lua` 改为发 `tigerest-apply-profile` 消息）和 Alt+1/2/3 都由 `PlayerComponent::applyQualityProfile` 按当前 mpv.conf 的档位内容逐项设置，并核对着色器数量。所以编辑器保存后无需重启就生效。档位里没写的项保持当前值，这一点与 mpv 自己的 `apply-profile` 一致。
- **保存后实时生效的范围**：全局选项（删除的项恢复默认值）、`@user-` 滤镜（重建在滤镜链最前面）、当前档位。`profile-cond` 这类自动档位只在启动时由 mpv 读取。
- **vf 只能写在全局部分**：写在档位里会在切档时整体替换滤镜链，因此校验直接报错。
- **启动档位的回退**：画质预设对应的档位被用户删掉时，尾部改用 `tigerest-default`，都没有时不写启动档位。
- **离开拦截**：「返回设置」、Esc 和设置页内切换分类都会先弹窗；通过 Emby 左侧导航离开无法拦截，这时保留草稿，离开后弹窗提供「强行使用 / 返回修改」。
- **报错位置**：错误行在编辑区背景标红、行号旁有圆点（悬停显示原因），完整列表在编辑器下方，点击跳到对应行；没有把文字写在行尾。
- **粘贴确认**：粘贴内容含管理区标记或超过 40 行时，先显示用户区的逐行差异，确认后才替换。
- **RIFE 提示**：开关 RIFE 后，播放器通过 `mpvConfMessage` 信号通知设置页，在底部状态栏显示暂停或恢复了几行。
- **测试注入口**：自动化测试需要私有 IPC 端点等选项时，设置环境变量 `TIGEREST_MPV_TEST_OPTIONS`，内容写在尾部管理区最后；Windows 的 RIFE 测试已改用它。
- **诊断**：`mpvDiagnostics` 新增 `videoFilters`（当前滤镜链，按顺序）。
