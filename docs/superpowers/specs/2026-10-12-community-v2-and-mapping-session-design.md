# 公共评论 v2 与弹幕会话授权前端设计

日期：2026-10-12。依据用户提供的 `X:/FRONTEND-HANDOFF-2026-10-12.md`，以及本会话已确认的“所有合法大河登录用户默认可保存共享绑定”。本设计描述客户端接线；后端部署和管理后台不在本次修改范围。

## 用户体验与范围

大河用户登录 Emby 后直接使用公共评论和共享弹幕保存，不需要新账号或授权 JSON。自建 Emby 用户正常播放，进入公共评论时使用单独的评论账号；自己的 Emby Token 不会发送给大河。原有私人评论、报错、日志和修复通知继续可用。

沿用已有详情页评论布局、分页、回复和消息面板，增加账号与公共/本服范围入口。Windows 交付可运行的预览包并验证退出/重开；共享 JavaScript 和原生桥接同步适配 macOS、Android，实际可运行的测试与仅代码/构建覆盖分开记录。播放器音量问题作为独立修复恢复正确的音量记忆，不改为强制每次启动100。

## 方案选择

推荐共享 JavaScript 管理会话和界面，平台原生层提供限定目的地的 HTTP 请求和安全凭据存储。这样外服 Emby 的网页来源不会被公共服务 CORS 拦住，现有三端共享界面也无需复制实现。

纯网页 fetch/localStorage 方案改动少，但外服 Origin 不在后端白名单，且令牌持久保存不满足交接约定。为每个平台另写一套公共评论界面则会重复现有回复、分页和消息逻辑；本次不采用。

## 原生通信与凭据

新增小型社区桥接模块，通过现有 SystemComponent / Android BridgeDispatcher 暴露异步请求、取消、凭据读写；不把公共服务做成任意 URL 代理。v2 目的地固定为 `http://nas.tigerest.top:18443/community/v2`，保持真实 Host，禁止重定向携带凭据到其他目的地。请求大小、方法与路径符合交接表，日志只记操作、状态码和可公开 requestId。

Windows 使用系统凭据存储，macOS 使用 Keychain，Android 使用 Keystore 保护的加密数据。凭据按应用配置及当前 Emby 账号上下文隔离，不进入普通设置、网页 localStorage、诊断或导出。平台存储不可用时保持内存会话并明确无法记住登录，不以明文文件替代安全存储。

JavaScript 的统一会话模块负责能力发现、可信 ServerId 规范化比较、Emby 交换/独立账号登录、单飞刷新、退出、密码修改和代际取消。收到旋转刷新结果后，先保存新令牌再放行业务请求；刷新结果丢失不重用旧 Refresh，转为重新交换或要求登录。503 保留已有内容；401 只允许一次相应重新认证，避免循环。

## 弹幕授权

自动读取仍匿名，并优先于历史和旧匹配。手动选择时检查映射能力，同时使用 v2 能力返回的可信 ServerId 判断当前账号；不硬编码 ServerId，也不把独立评论 Bearer 用于映射。

原生层仅为当前可信 Emby 会话建立私有临时授权头，桌面 Lua 只接收路径和非敏感会话代号；三个 Emby 头不进入 subprocess 参数。Android 由原生请求层加入当前有效会话头。退出或切换账号时取消旧请求、撤销旧临时授权，并让迟到响应失效。缺少权限仍可手动取所选弹幕，明确共享未保存；已有429等待逻辑保留。

旧能力接口404按原协议兼容。旧管理员令牌仅保留已有受信任客户端的兼容通道，不成为新用户的配置步骤，也不能让外服身份自动获得写权限。

## 公共评论与媒体键

评论客户端保留 v1 私人接口，新增 v2 公共客户端，共用现有正文、幂等发送、分页、删除占位和错误呈现规则。大河用户进入评论时透明交换，外服用户看到评论账号登录/注册入口；能力故障显示暂不可用，不误导注册。注册仅在后端启用时出现，账号页提供独立账号退出和修改密码。

默认展示公共评论。大河用户保留明确标记的“本服评论”入口和“上报问题”；外服不显示无权限的私人入口。影片/整剧采用自身 TMDB；季/单集通过所属剧集取得作品 TMDB，单集再带正常播出季集编号。缺失可靠身份、DVD/合并集或不确定顺序时不猜测 aired：大河可切本服评论，外服说明暂不支持该媒体共享评论。

公共头像使用默认头像，v2不展示管理操作。新旧通道各自保存分页、草稿和待发UUID；切换通道/媒体/账号后旧结果不能覆盖新状态。只有同一发送的失败重试复用同一UUID和正文。

## 消息与跨服跳转

大河用户继续以 v1 统一消息作为通知来源，保留公共回复、私人回复和报错修复，避免再叠加 v2 同一作者的公共回复和未读数。外服独立账号使用 v2 公共消息及“我的评论”。界面标明各自范围，GET 不自动已读，“全部已读”使用对应接口最新快照。

v2跳转按标准 media 键查询当前用户自己的媒体库。只接受唯一且元数据吻合的条目；找不到或有歧义时仍打开公共讨论并说明无法定位本地媒体，不猜 Item.Id。评论定位使用 root/comment anchor 分页，不能将 anchor 和 cursor 同时发送。

## 验证与交付

为能力/凭据隔离、可信GUID比较、外服不泄露Token、刷新单飞及结果丢失、退出竞态、HTTP错误、TMDB/季0/未知编排、消息去重和导航添加行为回归。使用实际 WebEngine 和隔离账号 fixture 验证登录、评论、消息与失败UI；生产接口联调和 fixture 结果单独记录，不向公共评论区发送测试文字。

音量验证覆盖新配置100、自定义37、合法0，分别以红叉和Alt+F4退出后重开；不得污染安装版设置。原生测试遵守 `dev/windows/TESTING.md`，每次先在同一PowerShell调用中加载运行库环境。

完成后提供预览包、验证记录和未能在本机实际验证的平台/公网条件。后端要求的另一公网检查若没有独立出口，只报告未验证，不把本机域名访问算作另一公网。
