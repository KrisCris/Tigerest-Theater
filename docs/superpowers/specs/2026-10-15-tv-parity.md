# TV parity increment

User physically verified the first tvOS client but rejected its simplified page design. Preserve the established Tigerest home and browsing semantics: dark/gold artwork-based library rail, selected-library featured work, 24-card work-level carousel, continue-watching/recent state, favorites, original detail/season/episode navigation and SXXEXX. Use native focus controls for the Siri Remote; no WebKit workaround. Existing home JS and community JS are the behavior specification.

Add the existing shared danmaku matcher/search/cache and display-link renderer with a small host abstraction rather than a second matching implementation. Include auto and manual matching, enabled toggle, per-source delay, and explicit shared-correction choice. Keep token isolation and provider retry/429 rules. No RIFE on television.

Add usable native comments from media details: private/public channel selection where supported, episode/work scope, paginated comments and replies, composition/reply and own-comment removal using existing server permissions. Public self-host identities use independent community login; trusted Emby identity may use the established exchange/private channel only after capability/server-ID verification. Preserve failed-send drafts and idempotency keys. Tests must not send production comments.

Mount the same bundled desktop tigerest-default preset (high-quality, SSimDownscaler_RT, KrigBilateral, RAVU) with a native-quality fallback and outside-player setting. No silent substitution or claim that accepted settings prove HDR/ICC support. Validate actual playback/shader passes on the paired second-generation Apple TV.

The separate Mac/iPad request is an installation restriction change, explicitly not an old-system support claim. Preserve release2.7.0/code payload, stage copies, adjust material installation metadata to15.0, preserve intentional static-framework sentinels, re-sign Mac/repackage unsigned iPad, verify hashes/signatures/current-system execution, then replace only Apple release attachments. Do not announce compatibility or alter other-platform assets/tag. Keep source/provenance and checksum artifacts accurate for the resulting packages.

Follow-up from physical testing: each episode detail must remain useful on its own, with season/episode selection, available year/runtime/genre/people/media information, and inline comments. The player also needs actual previous/next and episode-picker actions. Episode switching must reuse the same catalogue and preserve browsing return context; changing a selection must not create an ever-growing stack of detail pages. Missing server metadata should be omitted rather than invented.
