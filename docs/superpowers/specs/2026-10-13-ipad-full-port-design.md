## 2. 架构选择

现有桌面客户端不是独立维护一套 Emby 媒体库前端，而是加载服务器提供的 Emby Web，并注入 `native/` 中的主题、播放、弹幕接口、评论、消息和设置扩展。Android 已经以独立平台壳和桥接层复用了这些代码。

| 路线 | 与本次目标的关系 |
| --- | --- |
| **原生 Swift 应用壳 + WKWebView + 原生 libmpv（推荐）** | 保留 V2.6.0 的页面、业务行为和深色金色样式；重点完成 WebKit 兼容、iPad 桥接、原生播放与文件能力。适合首版尽量完整移植。 |
| 全部页面重写为 SwiftUI + libmpv | 有利于完全原生的浏览界面和后续 tvOS 界面，但需要重新实现首页、详情、评论账号、管理、消息和设置，首版更容易遗漏已有行为。 |
| WKWebView + AVPlayer | 原生系统播放接入较直接，但多格式和 ASS 字幕的处理路线会改变，不能作为保留现有 MPV 体验的默认实现。 |

推荐工程新增在 `apple/`。SwiftUI 管理应用入口和原生辅助页面，UIKit 承载 WKWebView、播放视图、文件选择和触控协调。媒体解码、音画时间轴和字幕使用应用内 libmpv。视频不是交给网页播放器或外部 App。

网页扩展在构建时从仓库的 `native/` 生成只读资源，避免手工复制出另一套评论和设置实现。平台差异由明确的能力描述控制，例如 `platform: ipad`、`downloads`、`nativePlayback`、`desktopWindowControls`，不把 iPad 冒充 Android 来绕过分支。对共享 JavaScript 的修改必须回归桌面与 Android 已有行为。

tvOS 后续使用适合遥控器焦点导航的原生界面；本期的 WKWebView 页面复用方案不被当作 tvOS 界面实现。共享模块不依赖 WKWebView 或 iPad 控件。

## 4. 组件和数据流

| 组件 | 职责 |
| --- | --- |
| `AppleCore` | 服务器地址与身份、平台能力、桥接消息模型、设置校验、播放队列、弹幕数据和下载状态；不依赖网页或具体视图。 |
| `WebHost` | WKWebView、服务器导航、登录站点数据、文档开始时注入、共享资源、加载失败和页面恢复。 |
| `NativeBridge` | 适配现有 `window.api` 方法/信号，参数校验、异步响应、取消、页面代次和调用来源校验。 |
| `PlaybackController` | libmpv 生命周期、解码与渲染视图、音频会话、轨道、进度、队列和故障回收。 |
| `PlayerControls` | 触控、键盘、全屏播放区、播放菜单和诊断展示；只通过控制器操作媒体。 |
| `DanmakuRepository/Timeline/Overlay` | 服务协议与缓存、当前媒体匹配、来源、时间轴和原生绘制。 |
| `CommunityTransport/CredentialStore` | 沿用已有评论协议，处理系统网络代理、会话隔离、Keychain 凭据及头像上传。评论和消息视图继续复用共享页面。 |
| `DownloadStore/DownloadCoordinator` | 下载任务、持久化、续传、后台 URLSession、文件校验和离线元数据。 |
| `Settings/ProfileStore` | 有类型的设置、能力过滤、恢复默认、配置档切换及数据目录。 |
| `Diagnostics` | 限量环形日志、来源脱敏、按账号/服务器范围收集、设备与播放诊断。 |

典型播放流：Emby 页面选片 → 共享播放插件取得播放信息 → 桥接校验请求 → libmpv 播放 → 原生控制器回传状态 → 共享插件向 Emby 同步进度。弹幕使用同一播放会话的媒体身份与时间，不自行维护与视频脱节的计时器。

离线入口必须由原生壳直接访问：断网或服务器网页加载失败时仍能列出已下载内容并启动 libmpv。不能把离线媒体管理完全依赖于在线 Emby 页面的成功加载。

## 5. WebKit 与桥接规则

1. 在顶层文档开始时完成桥接和共享扩展注入。服务器源、端口和子路径分别保留，重新导航不能漏装桥接。
2. 接受的消息必须来自主 frame 和当前已选择服务器的允许源，或应用自己的连接引导页。第三方 iframe、外站导航、旧页面回调和任意本地路径不能获得原生能力。
3. 用显式方法表与类型校验适配 `player`、`settings`、`system`、`window`、`danmaku`。保留现有回调/Promise 和信号顺序约定；未知方法返回明确的不支持错误。
4. 页面重载、切换账号/服务器/配置档时增加代次并取消旧请求。旧会话的图片、评论、弹幕和播放回调不能写入新页面。
5. 共享脚本、样式和图片是应用包内的版本化资源；通过受限资源处理器及预注入提供。必须验证 HTTPS 页面中的资源访问、MIME、字体与跨源限制，不以关闭全部安全检查作为解决方案。
6. 保留正常 TLS 验证。连接用户选择的 HTTP 或局域网服务器时配置所需 ATS 和本地网络使用说明；拒绝本地网络授权时显示可恢复提示。跨源重定向不得携带 Emby 或评论凭据。
7. WebKit 登录站点数据按配置档隔离。评论凭据进入 Keychain；账号退出清理相应会话和敏感缓存。日志不记录密码、完整认证 URL、Cookie、Token 或认证头。

## 6. 播放、画质和交互

采用构建时固定来源、版本和 SHA-256 的 iOS arm64 libmpv/FFmpeg/libass 组件，包含相应源码来源和许可说明。模拟器组件单独管理，不混用 macOS 或 Mac Catalyst 架构。首次运行不在线下载播放器内核。

MPVKit 可作为 iOS 构建和接入参考，但上游明确提示维护频率有限且 Metal 路径包含补丁，不能因为它提供包就直接认定生产可用。实施首先验证固定构建的启动、VideoToolbox 解码、渲染、音画同步、字幕和销毁；未通过时修正或自建相同 libmpv 路线，不能静默换成能力更少的播放器。

播放控制器由单一所有者串行管理。快速切集时先完成旧媒体停止，再启动新媒体；停止、错误、取消和自然结束只收尾一次。网页重载和视图尺寸变化不重复创建播放器。开始加载 30 秒无有效进展时退出加载状态并允许重试；持续播放的网络缓冲由独立状态处理。

硬解和格式声明基于当前设备与已编译组件。覆盖 MP4/MKV、H.264/HEVC、10 bit、常见音频及 ASS/SRT；AV1 在有相应解码路径时测试并如实记录软/硬解。HDR10、HLG 和 Dolby Vision 分格式验证色彩与实际输出，不承诺所有 Dolby Vision profile 或音频直通均与桌面相同。设备不支持的路径由明确的软件解码、色调映射或服务器协商处理。

横竖屏、分屏和 iPad 窗口尺寸变化以当前可用窗口为准；操作按钮避开安全区、键盘和系统手势边缘。系统限制旋转时遵守限制。播放会话、位置、字幕、选集与页面滚动位置在布局变化中保留。

音量通过公开系统控件和播放器增益区分处理，不用私有接口模拟 Android 全局音量行为。亮度调整只影响本次播放，离开播放器恢复原值。退出播放器恢复进入前的页面和界面状态。所有关键操作都可通过可见按钮完成，手势不是唯一入口。

画质预设、滤镜、缓存、硬解和高级参数按 iPad 能力提供。沙盒外脚本、外部进程调用、Homebrew 路径、桌面显示输出控制不作为可导入配置执行。无法适用的设置显示清楚原因或从能力列表移除，不能保存后静默无效。

## 7. 弹幕、评论、消息和报错

共享页面和协议以 V2.6.0 为准。评论账号的注册与密码规则由服务端能力返回决定；大河与自建身份、头像同步、作品身份映射、权限管理、分页和消息读取沿用当前语义。

原生弹幕参考 Android 已拆分的 Repository、Match、Parser、Timeline、Clock 和请求代次设计。用屏幕帧时钟绘制，以 libmpv 媒体时间为基准；暂停、缓冲、拖动和倍速变化同步更新。旋转后重新分配轨道，避免旧轨道越界或重复弹幕。

来源搜索、匹配和下载遵守已有取消与重试规则。只对短暂失败进行有上限的重试，不能对空结果、权限失败或限流不停重试。导入文件需要大小、格式和解析错误边界；源数据只作为数据解析。

生产评论、回复、删除、禁言、报错和共享纠正均是写操作。自动化通过本地受控测试服务验证写路径；真实服务的初步联调以读取和真实播放为主。实际发布公开评论或问题报告时使用用户明确指定的测试内容和对象，避免在生产服务制造测试垃圾。

## 8. 下载、离线和配置档

下载身份由服务器、账号、配置档、媒体项和来源共同确定。入队前尊重服务器的下载权限。任务使用应用私有目录和系统后台传输，保存状态和部分文件；进程被系统终止与用户强制退出的行为分别记录，不承诺绕过系统调度限制。

续传使用服务端验证器和范围响应：校验 ETag/Last-Modified、HTTP 206 的 Content-Range；服务器返回 200 时安全重新下载；416 或文件内容已变化时验证并恢复，而非把两份内容拼接。空间不足、认证失效、Wi-Fi 中断和重启后都显示可操作状态。完成前不得把部分文件标记为可用。

离线记录保存足够的标题、封面、媒体身份、轨道和本地资源信息。用户选择保存的外置字幕及已有弹幕缓存可随媒体离线使用；仅保存视频不能声称已保存所有字幕或在线评论。恢复联网后可同步观看进度，按账号隔离并防止旧记录覆盖更新的观看状态。

删除下载只作用于本配置档的本地文件和记录。应用升级保留配置及下载；换 Personal Team、Bundle ID 或卸载造成的数据边界在安装说明中说明。配置档切换应停止或明确归属当前播放与任务，不让凭据、文件列表或离线进度跨账号串用。

## 9. RIFE 专项验证和发布边界

RIFE 纳入本次移植评估，不能仅因 Android 没有就默认忽略。现有 Mac 路径依赖带补丁的 mpv、VapourSynth 79、嵌入式 Python 以及 Core ML/Metal 插件，需要检验可复用的推理代码和 iOS 的帧接入方式。

验证分为模型正确性、播放帧接入、连续性能三项。目标沿用 Mac：逐行、恒定帧率、SDR、最高 1080p/30 输入，2 倍输出；HDR/VFR/隔行等不适用内容保持普通播放。推理结果必须正确衔接 mpv 的音画时间轴、字幕和末帧，而不是从界面截图后另行播放。

只有完整链路在 M5 真机持续播放至少 10 分钟、音画同步与画面检查通过、切集和定位可靠、资源占用可控且性能不足能回退时，才把 RIFE 作为可启用功能交付。不能用几次模型推理速度代替整个播放器的实时能力，也不能由 M5 达标推断所有 iPad 都支持。

若需要大幅修改解码器或无法在上述范围稳定运行，首版交付其他已经验收的完整功能，并明确标注 RIFE 未支持、原因与测试证据；不提供假开关。此条件边界随设计获准推进；不能因此跳过 RIFE 专项评估。

## 10. 验证与交付

实施可以拆为四组互相集成的工作：应用壳和桥接；播放器与设置；弹幕与社区功能；下载离线与整体验收。各组有独立测试，全部完成后才形成首版；RIFE 的专项结果随整体报告交付。

必要验收包括：

- 固定 Xcode 27 beta 工具链，工程和依赖最低部署目标一致；iPadOS 26 构建检查，并在可用的 26 系统模拟器或真机验证兼容路径。若仅完成 27.2 真机验证，明确报告 26 实测缺口。
- 用 Personal Team 完成签名、无线安装和启动，重复安装保留应用数据；首次签名的 Apple 提示由用户处理，不要求用户提供密码或双重认证码给脚本。
- 受控服务验证 HTTP/HTTPS、子路径、失败重试、非允许源桥接拒绝、账号切换与旧响应失效；凭据不出现在日志或测试快照。
- 真机实际播放多种媒体及字幕，至少 20 次切集/停止/重播和 20 次定位；覆盖旋转、窗口变化、键盘、锁屏、中断和返回页面。
- 弹幕暂停、拖动、倍速、换源与切集一致；社区页面覆盖账号、头像、评论、消息、报错及失败后的草稿/幂等行为。
- 下载覆盖暂停恢复、断网重连、重启、内容变化、空间不足、认证失效和断网离线启动；配置档隔离有效。
- 画质、HDR 和 RIFE 分别记录实际设备、素材属性和结果。没有对应测试的功能不写“已验证”。
- 共享网页改动运行相关 Node 回归及桌面/Android 桥接测试，不把 Windows 原生测试在未加载规定环境时直接启动。

最终交付 Xcode 工程、源代码、锁定依赖和来源清单、构建/签名/安装说明、可由当前账号安装的构建产物、文件校验值，以及按功能列明通过/失败/未验证的报告。免费签名产物不能被描述为任何人都能直接安装的通用发行包。
