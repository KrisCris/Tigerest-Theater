# 消息与私人问题上报

## 打开消息中心

点击顶栏「消息」。在窄屏上，顶栏可能收进二级菜单；消息入口仍用于跨作品查看回复和自己的发言。

| 页签 | 内容 | 可用范围 |
| --- | --- | --- |
| 收到的消息 | 别人直接回复你的内容；大河还包含问题修复通知 | 已登录的评论身份 |
| 我的发言 | 自己发表过的评论和回复 | 已登录的评论身份 |
| 我的报错 | 自己提交的问题、处理状态与修复说明 | 大河用户 |

自建用户登录独立评论账号后查看公共消息。大河使用统一消息列表，公共回复、本服回复和修复通知按服务权限显示，避免同一条通知重复出现。

列表支持继续加载。网络暂时失败时，已加载内容会保留，稍后刷新即可；退出、登录失效或切换账号会清空旧身份内容。

## 从消息返回讨论

点击讨论消息可打开原讨论并定位评论。公共消息来自另一个服务器时，客户端会尝试在你自己的媒体库中寻找唯一对应作品或单集。

如果本地不存在这部作品、找到多个不确定候选，或原条目已不可访问，客户端不会随意打开另一部作品；仍可进入公共讨论查看。公共评论不会把对方服务器的影片播放权限分享给你。

「全部已读」处理当前服务端快照内的消息。操作后新到的消息仍会保持未读，所以红点再次出现不一定是操作失败。

## 什么时候用“上报问题”

大河电影、剧集或单集详情页提供「上报问题」。适用于播放异常、字幕缺失、字幕错误或其他媒体问题；季详情没有该按钮。

报错是发给服务维护者处理的私人记录。它不会出现在公共评论区。自建服务器的媒体问题，请联系自己的服务器维护者；公共评论账号不提供大河私人报错权限。

## 提交步骤

1. 在发生问题的作品或单集详情点击「上报问题」。
2. 选择「播放异常」「字幕缺失」「字幕错误」或「其他」。
3. 填写 3–2000 字说明。建议包含“做了什么、实际发生什么、希望怎样”。
4. 如果问题发生在片中某时刻，填写「分钟」和「秒」。不清楚时可留空；填 0 分 0 秒表示开头，和未填写不同。
5. 保留或取消「附带诊断日志」，然后提交。
6. 从「消息 → 我的报错」查看记录。

有用的说明示例：

> 第 3 集 12 分 34 秒开始，中文字幕比对白早约 2 秒，之后一直如此。选择另一条字幕正常。

尽量写清具体单集、字幕轨、时间点和现象，比只写“播放不了”更容易定位。

## 诊断日志包含什么

默认勾选「附带诊断日志」，可在提交前取消。客户端收集当前账号、当前配置和当前运行会话中最近约 10 分钟的应用记录，最多 1 MiB。

记录会先脱敏，处理密码、令牌、认证头、私人账号信息和本地绝对路径等内容。Android 和 iPad 使用应用内日志，无需连接电脑，Android 也不需要启用 ADB；这不是上传整台设备的系统日志。

没有可用日志时仍可提交文字报错。日志仅报错本人和后台所有者按权限访问，默认保存 30 天；报错处理记录继续按服务规则保留。手动上传到公开 GitHub Issue 的截图和文件仍应自行检查隐私。

## 提交成功但日志失败

文字报错和日志分两步提交。已经显示报错成功、但日志上传失败时，使用「重试日志附件」；这会重试同一份附件，不会再次创建报错。

网络故障时草稿可保留；在原表单重试即可。提交过程中按钮会锁定，避免重复发送。离开当前详情、关闭表单、退出或切换账号会终止待发任务并清理当前快照。

## 查看处理结果

「我的报错」显示「待处理」或「已修复」。打开记录可以阅读管理员的修复说明；收到修复通知时也能从「收到的消息」打开。

即使原影片被删除或当前账号无法再访问，已收到的修复说明仍可查看。被限制评论发言时，问题上报仍独立处理。

客户端自身崩溃、更新安装失败等问题，适合提交[GitHub Issue](https://github.com/Tigerest/Tigerest-Theater/issues)。准备信息见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
